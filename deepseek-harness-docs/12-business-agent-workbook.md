# 业务 Agent 实战练习册

> 目标：把前面的概念、设计、测试串成一套可执行的学习练习。读完前 11 篇后，可以直接按这份练习册做一个完整的小项目。

这不是再讲一遍理论，而是给出一条实践路径。

```text
选一个场景
  -> 拆业务
  -> 画流程
  -> 写 Tool 卡片
  -> 设计 Plugin / Profile
  -> 准备样例
  -> 做验收
  -> 复盘
```

---

## 1. 这份练习册适合谁

适合下面这种学习方式：

- 想快速熟悉 deepseek-harness。
- 不想只停留在概念理解。
- 希望能把东西落到业务场景里。
- 想先做一个小而完整的 MVP。

不适合一上来就做：

- 全平台架构设计。
- 大规模生产系统改造。
- 多业务线统一治理。

练习册的核心原则：

```text
小场景
清边界
可验收
能复盘
```

---

## 2. 推荐练习场景

如果你还没决定做什么，优先选下面 3 类之一：

| 场景 | 优点 | 风险 |
|------|------|------|
| 客服工单分派 | 容易理解，流程清楚 | 需要处理高风险投诉 |
| 档案自动归档 | 适合练流程和审计 | 字段较多 |
| 运维巡检报告 | 适合练批处理 | 需要控制自动修复边界 |

### 推荐顺序

1. 客服工单分派
2. 档案自动归档
3. 运维巡检报告

原因：

- 输入相对直观。
- 结果容易评估。
- 风险边界容易画清。

---

## 3. 第一步：写场景说明

先别写代码，先写一段清楚的场景说明。

模板：

```text
业务场景：

当前人工做法：

希望 Agent 帮助完成的部分：

本次 MVP 只覆盖：

本次 MVP 不覆盖：

哪些动作必须人工确认：

成功标准：
```

例子：

```text
业务场景：
  客服工单自动分派

当前人工做法：
  客服先读工单，再判断类型、紧急程度和责任部门，最后创建分派记录

希望 Agent 帮助完成的部分：
  自动查询规则、判断分类、生成分派建议、提示高风险工单

本次 MVP 只覆盖：
  单条工单、测试环境、3 个核心工具

本次 MVP 不覆盖：
  自动通知客户、全量系统接入、复杂 SLA

哪些动作必须人工确认：
  高风险工单创建分派记录

成功标准：
  10 条样例里高风险 100% 停住，普通样例大部分能给出正确建议
```

---

## 4. 第二步：画主流程

把任务从头到尾画出来。

模板：

```text
输入
  -> 查询
  -> 判断
  -> 确认
  -> 写入
  -> 审计
  -> 输出
```

客服工单示例：

```text
输入工单
  -> 查询分派规则
  -> 查询客户信息
  -> 判断类型和风险
  -> 高风险人工确认
  -> 创建分派记录
  -> 写审计日志
  -> 输出处理报告
```

练习要求：

- 先画主流程。
- 再加分支。
- 再加失败处理。

不要一开始就把所有异常都画进去。

---

## 5. 第三步：写 Tool 卡片

每个工具都写一张卡片。

模板：

```text
Tool 名称：

业务动作：

输入字段：

输出字段：

是否只读：

是否会修改业务状态：

风险级别：

是否需要人工确认：

失败后怎么处理：

需要记录哪些审计字段：
```

### 练习要求

至少写 3 个 Tool：

1. 查询类 Tool
2. 写入类 Tool
3. 审计类 Tool

### 客服工单例子

```text
Tool 名称：
  query_routing_rules

业务动作：
  查询工单分派规则

输入字段：
  ticket_text

输出字段：
  candidate_departments
  high_risk_keywords

是否只读：
  是

风险级别：
  L1

是否需要人工确认：
  否

失败后怎么处理：
  转人工

需要记录哪些审计字段：
  ticket_id, tool_name, tool_input, tool_output
```

---

## 6. 第四步：写 Workflow 卡片

把主流程拆成节点。

模板：

```text
节点名称：
节点类型：
输入：
动作：
输出：
成功后下一步：
失败后下一步：
是否需要人工确认：
是否写审计：
```

### 练习要求

至少写这 5 类节点：

1. 触发节点
2. 查询节点
3. 判断节点
4. 确认节点
5. 审计节点

### 练习提示

如果一个节点里放了太多事情，通常说明：

- Tool 太粗了。
- 或 Workflow 节点切得不对。

---

## 7. 第五步：设计 Plugin / Profile

把业务能力打包。

### Plugin 卡片模板

```text
Plugin 名称：

负责哪个业务域：

包含哪些 Tool：

包含哪些 Workflow：

包含哪些规则：

包含哪些 Adapter：

包含哪些审计能力：
```

### Profile 卡片模板

```text
Profile 名称：

用途：

使用什么数据源：

是否允许写入：

是否需要人工确认：

是否用于开发 / MVP / 影子运行 / 生产试点：
```

### 练习要求

至少设计 3 个 Profile：

- 开发
- MVP
- 试点

---

## 8. 第六步：准备样例集

没有样例集，就没法验收。

### 至少准备这些样例

| 类型 | 数量建议 |
|------|----------|
| 正常样例 | 10 条 |
| 边界样例 | 5 条 |
| 高风险样例 | 5 条 |
| 数据缺失样例 | 5 条 |
| 工具失败样例 | 5 条 |

### 样例卡片模板

```text
样例 ID：

输入：

期望分类：

期望风险：

期望 Tool 调用：

是否需要人工确认：

期望最终状态：
```

### 练习要求

至少把 10 条样例写完整。

---

## 9. 第七步：做验收

验收时不要只看回答对不对。

要看：

- Tool 调用对不对。
- 高风险是否停住。
- 失败后有没有转人工。
- 审计是否完整。
- 业务人员是否看得懂。

### 验收记录模板

```text
样例 ID：

实际分类：

实际风险：

实际 Tool 调用：

是否进入人工确认：

实际最终状态：

是否通过：

问题说明：
```

---

## 10. 第八步：复盘

每次练习结束后，写复盘。

模板：

```text
练习场景：

做对了什么：

做错了什么：

哪些 Tool 需要重切：

哪些 Workflow 需要补分支：

哪些样例需要加入回归集：

下次准备优化什么：
```

复盘的目标不是写得好看，而是让下一轮更稳。

---

## 11. 一条完整的练习路线

你可以按下面节奏做：

```text
第 1 天：选场景 + 写场景说明
第 2 天：画主流程 + 写 Tool 卡片
第 3 天：写 Workflow + 设计 Plugin / Profile
第 4 天：准备样例集
第 5 天：做验收 + 复盘
```

如果时间更少，最少也要做这 4 件事：

```text
场景说明
主流程图
3 个 Tool 卡片
10 条样例
```

---

## 12. 最后建议

如果你只是想“快速熟悉 deepseek-harness”，这套练习册已经够用了。

如果你想“以后能在业务里落地”，就不要跳过样例、验收和复盘。

原因很简单：

```text
概念理解让你知道它是什么
练习册让你知道它怎么落地
样例和复盘让你知道它能不能上线
```
