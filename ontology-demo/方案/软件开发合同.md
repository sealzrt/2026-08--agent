## 第四条 项目功能范围及功能清单

### 4.1 功能范围总述

本项目涵盖供应链管理的核心业务流程，面向甲方内部运营人员、采购人员、仓储人员及外部供应商提供 Web 端管理后台及移动端轻应用。

| 模块编号 | 模块名称 | 功能描述 | 优先级 |
|---------|---------|---------|-------|
| M01 | 用户与权限管理 | 多角色权限体系（RBAC）、SSO单点登录、操作审计日志 | P0 |
| M02 | 采购管理 | 采购申请、审批流、采购订单、到货确认、采购退货 | P0 |
| M03 | 库存管理 | 入库/出库/调拨/盘点、安全库存预警、批次/序列号管理 | P0 |
| M04 | 物流跟踪 | 运单管理、物流状态实时追踪、异常预警、电子签收 | P0 |
| M05 | 供应商协同 | 供应商门户、在线报价、订单确认、对账结算 | P1 |
| M06 | 数据分析与报表 | 供应链KPI看板、多维度报表导出、自定义报表引擎 | P1 |
| M07 | 消息与通知中心 | 站内消息、邮件、短信、企业微信多通道通知 | P1 |
| M08 | 系统管理 | 数据字典、流程配置、参数配置、数据备份与恢复 | P0 |
| M09 | 移动端轻应用 | 审批、库存查询、物流跟踪、预警接收（企业微信H5） | P2 |
| M10 | 开放接口平台 | 标准RESTful API、Webhook、与甲方现有ERP系统对接 | P1 |

## 第五条 技术要求

### 5.1 技术架构

| 层次 | 技术选型 |
|------|---------|
| 前端 | Vue 3 + TypeScript + Element Plus |
| 后端 | Java 17 + Spring Boot 3 + Spring Cloud Alibaba |
| 数据库 | MySQL 8.0（主库）+ Redis 7（缓存）+ Elasticsearch 8（检索） |
| 消息队列 | Apache RocketMQ |
| 容器化 | Docker + Kubernetes（K8s） |
| CI/CD | GitLab CI + ArgoCD |
| 监控 | Prometheus + Grafana + SkyWalking |

### 5.2 性能指标

- 核心页面响应时间 ≤ 2秒（95th percentile）
- 系统并发用户支持 ≥ 500人
- 接口TPS ≥ 1000（核心查询接口）
- 系统可用性 ≥ 99.9%（月度）
- 数据库单表支撑 ≥ 5000万行（含分库分表方案）

### 5.3 安全要求

- 通过等保二级安全要求
- 传输层全链路HTTPS加密
- 敏感数据AES-256加密存储
- 支持OWASP Top 10防护
- 完整的操作审计日志，保留期 ≥ 180天

### 5.4 兼容性要求

- Web端：Chrome 90+、Edge 90+、Firefox 90+、Safari 15+
- 移动端：企业微信内置浏览器（iOS 14+ / Android 10+）
- 屏幕适配：1920×1080（主）、1366×768（兼容）

### 5.5 部署环境

- 生产环境：甲方私有云环境
- 测试环境：乙方负责搭建
- 乙方需提供完整的容器化部署方案及运维手册

## 第十一条 验收标准和流程

### 11.1 验收标准

#### 功能验收标准

| 优先级 | 验收要求 |
|-------|---------|
| P0功能 | 100%实现，无致命/严重缺陷遗留 |
| P1功能 | 100%实现，允许遗留不超过3个一般缺陷（须有规避方案） |
| P2功能 | 实现率 ≥ 80%，未实现部分不影响系统整体运行 |

#### 缺陷等级定义

| 等级 | 定义 | 处理要求 |
|------|------|---------|
| 致命（S1） | 系统崩溃、数据丢失、核心流程完全阻断 | 上线前必须清零 |
| 严重（S2） | 核心功能异常、数据错误、无规避方案 | 上线前必须清零 |
| 一般（S3） | 非核心功能异常，有规避方案 | 允许遗留，维保期修复 |
| 轻微（S4） | UI瑕疵、文案错误、体验优化建议 | 允许遗留，纳入后续迭代 |

#### 性能验收标准

- 满足本合同第5.2条所列全部性能指标。

#### 文档验收标准

- 交付物清单（第九条）所列全部文档齐全、内容完整、与系统实际一致。

### 11.2 验收流程

项目验收按以下六个阶段依次推进：首先由乙方开展自测（集成测试与回归测试），输出《测试报告》；随后进入甲方UAT测试阶段，测试周期为**10个工作日**，输出《UAT测试报告》；之后乙方完成缺陷修复与回归验证；系统进入**15个自然日**的试运行阶段；试运行通过后召开终验评审会；最终双方签署《终验报告》，完成项目验收。

### 11.3 验收结论

- **通过：** 满足全部验收标准，签署《终验报告》，触发第四期付款。
- **有条件通过：** 存在少量遗留问题但不影响上线，约定整改期限（≤ 15个工作日）。
- **不通过：** 存在重大缺陷，乙方须在15个工作日内整改后重新申请验收。重新验收不超过2次，仍不通过的，甲方有权解除合同。
