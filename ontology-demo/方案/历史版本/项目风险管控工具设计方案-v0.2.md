## 1. 项目背景与业务价值

### 1.1 业务场景

项目实施的**全链路**包含以下关键业务对象及其生命周期：

| 业务对象 | 说明 | 典型风险信号 |
|---|---|---|
| 合同内容 | 交付范围、里程碑付款、验收条款、SLA | 范围模糊、验收标准缺失 |
| 项目计划 | 里程碑、任务分解、依赖关系、资源 | 计划不合理、依赖未识别 |
| 项目进度 | 实际 vs 计划偏差、延期、阻塞 | 里程碑延期、进度偏差超阈值 |
| 需求分析 | 需求清单、优先级、变更、确认状态 | 需求蔓延、需求未确认 |
| 产品方案 | 产品设计、功能范围、评审状态 | 方案未评审、范围超合同 |
| 技术方案 | 技术选型、架构、风险评估、评审 | 技术不成熟、方案未定稿 |
| 风险点管控 | 风险登记、等级、概率、影响、缓解措施 | 风险未跟踪、缓解措施未落实 |

### 1.2 业务价值

1. **主动识别风险**：不再靠项目经理"凭经验发现"，而是通过规则和推理自动发现风险信号（如：里程碑延期超过 X 天 → 自动触发进度风险）。
2. **全链路关联**：风险不是孤立的，合同条款影响需求，需求影响方案，方案影响进度——本体把这条链串起来，能看出"风险从哪里来、影响到哪里去"。
3. **提高质量与成功率**：风险前置暴露、缓解措施可跟踪、决策有据可查。
4. **沉淀组织资产**：本体模型本身是行业知识资产，可复用、可演进。

## 2. 核心设计理念：为什么用"本体"

| 对比项 | 传统项目管理软件 | 本体驱动方案 |
|---|---|---|
| 数据组织 | 各模块孤立表单（合同表、进度表...） | 统一语义模型：类 + 属性 + 关系 |
| 跨模块查询 | 靠 JOIN / 硬编码 | 语义推理 + 图查询 |
| 风险识别 | 人工登记为主 | 规则引擎 + 关系推演 + LLM 辅助自动触发 |
| 扩展性 | 加字段要改库 | 本体演进，加类/加关系即可 |

> 关键点：本工具的本体不是"画给专家看的概念图"，而是**可执行的语义骨架**——数据实例、查询、规则、风险识别全部建立在本体之上。

## 3. 领域本体建模草案（核心章节）

### 3.1 核心类（Class）

```
├── 合同 (Contract)            # 合同编号、金额、签订日期、交付范围、验收条款、里程碑付款
├── 项目 (Project)             # 项目编号、名称、客户、实施周期、项目经理、状态
├── 计划 (Plan)                # 里程碑(Milestone)、任务(Task)、依赖、负责人、计划起止
├── 进度 (Progress)            # 实际起止、进度百分比、偏差天数、状态
├── 需求 (Requirement)         # 需求编号、优先级、状态、来源、变更次数、确认状态
├── 方案 (Solution)            # 产品方案(ProductSolution)、技术方案(TechnicalSolution)、评审状态
├── 风险 (Risk)                # 风险类型、等级、概率、影响、缓解措施、状态
├── 干系人 (Stakeholder)       # 客户方、我方、角色（项目经理/需求/开发/实施/QA）
└── 文档 (Document)            # 合同文本、需求文档、方案文档、会议纪要
```

### 3.2 核心关系（Object Property）

```
Contract --约束--> Project          (合同约束项目范围)
Project  --包含--> Plan             (项目包含计划)
Plan     --包含--> Milestone/Task   (计划包含里程碑/任务)
Requirement --来源于--> Contract    (需求来源于合同条款)
Solution --实现--> Requirement      (方案实现需求)
TechnicalSolution --引入--> Risk    (技术方案引入技术风险)
Requirement --变更导致--> Risk      (需求变更导致范围风险)
Milestone --延期导致--> Risk        (里程碑延期导致进度风险)
Progress --偏差--> Risk             (进度偏差触发风险)
Risk --影响--> Plan/Milestone       (风险影响计划/里程碑)
Stakeholder --负责--> Task/Risk     (干系人负责任务/风险)
```

### 3.3 关键数据属性（Data Property）

- 进度类：`progress_percent`、`delay_days`、`is_blocked`
- 需求类：`change_count`、`is_confirmed`、`priority`
- 合同类：`has_acceptance_clause`（验收条款是否明确）、`payment_milestones`
- 风险类：`probability`、`impact`、`severity`、`mitigation_status`

## 4. 风险识别机制（本工具的灵魂）

> 已确认：**规则为主 + LLM 辅助**。

### 4.1 四层识别架构

| 层级 | 机制 | 说明 | 示例 |
|---|---|---|---|
| L1 规则引擎 | 确定性规则 | 基于本体属性触发 | 里程碑延期 > 7 天 → 进度风险 |
| L2 关系推演 | 推理传播 | 沿本体关系传导风险 | 需求变更 → 影响技术方案 → 影响进度 |
| L3 数据信号 | 阈值/异常检测 | 数据层面的偏差信号 | 进度偏差 > 20% → 预警 |
| L4 LLM 辅助 | 大模型分析（可选） | 从非结构化文本中识别风险信号 | 合同条款扫描、需求变更描述分析 |

### 4.2 预置规则示例（可配置）

```
规则1 [进度风险]   IF milestone.delay_days > 7           THEN 创建"里程碑延期"风险
规则2 [范围风险]   IF requirement.change_count > 3        THEN 创建"需求蔓延"风险
规则3 [验收风险]   IF contract.has_acceptance_clause=FALSE THEN 创建"验收标准缺失"风险
规则4 [方案风险]   IF solution.review_status != "已评审"    THEN 创建"方案未评审"风险
规则5 [联动风险]   IF requirement.change_count>3 AND solution.affects = "核心架构"
                   THEN 风险等级自动上调一级
```

### 4.3 L4 LLM 辅助设计（预留能力，可插拔）

| 项 | 设计 |
|---|---|
| 用途 | 从合同/需求文档文本中抽取风险信号；对已识别风险做描述性总结 |
| 接入方式 | 接口抽象（`RiskAnalyzer` 接口），默认"关闭"，配置 API Key 后启用 |
| 模型 | 兼容 OpenAI 兼容接口 / 本地 Ollama（可切换） |
| 边界 | LLM 输出仅作为**建议**，落库为风险必须经规则或人工确认，保证可控 |

### 4.4 风险量化

```
风险等级 = f(概率 probability, 影响 impact)
红(高) / 黄(中) / 绿(低)  三级展示，支持看板聚合
```

## 5. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3 + TypeScript + Vite | 单页面、组合式 API、生态成熟 |
| UI 组件库 | Element Plus | 中文生态、表单/表格能力完善 |
| 图可视化 | AntV G6 | 关系图/知识图谱可视化，本体关系展示 |
| 状态管理 | Pinia | Vue3 官方推荐 |
| 路由 | Vue Router 4 | SPA 路由 |
| 本地存储 | IndexedDB（Dexie.js 封装） | 已确认：纯前端 MVP，浏览器本地持久化 |
| 表格导入 | SheetJS (xlsx) / PapaParse | 已确认：Excel/CSV 导入 |
| 规则引擎 | 自研轻量规则 DSL（v1） | 避免过度设计，后续可接重型推理器 |
| LLM 接口 | OpenAI 兼容 / Ollama（可插拔） | 已确认：规则为主 + LLM 辅助 |

## 6. 功能模块设计（本体建模 + 业务管理并重）

```
Ontology Web（Vue3 SPA）
├── ① 仪表盘 Dashboard        # 项目列表、风险概览、里程碑状态、预警中心
├── ② 本体建模 Ontology Studio # 类/属性/关系可视化建模（Protégé 风格简化版）
│     ├── 类管理（Class Tree）
│     ├── 属性管理（Data/Object Property）
│     └── 关系画布（拖拽连线，G6）
├── ③ 业务数据管理
│   ├── 合同管理  Contract
│   ├── 项目计划  Plan / Milestone / Task
│   ├── 进度跟踪  Progress
│   ├── 需求管理  Requirement
│   ├── 方案管理  Solution（产品/技术）
│   └── 风险中心  Risk（登记、处置、缓解跟踪）
├── ④ 关系图谱 Graph View     # 全链路知识图谱可视化（G6）
├── ⑤ 规则引擎 Rules          # 风险规则配置（可视化表单式）
├── ⑥ 数据导入 Import         # Excel/CSV 导入（合同/需求/计划等）
└── ⑦ 设置 Settings           # 本体版本、导入导出、LLM 配置
```

### 6.1 页面路由规划

```
/dashboard      仪表盘
/ontology       本体建模
/contract       合同
/plan           计划
/progress       进度
/requirement    需求
/solution       方案
/risk           风险中心
/graph          关系图谱
/rules          规则配置
/import         数据导入
```

## 9. 风险与不确定性

| 风险 | 应对 |
|---|---|
| 本体建模过度设计 | 先建最小可用本体（MVP 核心类 ≤ 10 个），快速迭代 |
| 规则引擎复杂度失控 | v1 用简单 DSL + 前端可视化配置，避免引入重型推理器 |
| 纯前端存储局限 | 预留数据层接口，后续可平滑切换后端 |
| 用户录入负担 | 提供模板化录入、Excel 导入（M3） |
| LLM 结果不可控 | LLM 仅输出"建议"，落库必须经规则或人工确认 |
