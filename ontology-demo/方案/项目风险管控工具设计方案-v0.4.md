## 1. 业务场景与全链路边界

### 1.1 全链路三阶段（已确认）

```
[售前阶段] → [实施阶段] → [运维质保阶段]
  商机/投标      合同/计划/进度       运维事件/工单
  售前方案       需求/方案/风险       SLA/质保期
  报价评审                         质保期跟踪
```

### 1.2 各阶段业务对象与风险信号

| 阶段 | 业务对象 | 说明 | 典型风险信号 |
|---|---|---|---|
| 售前 | 商机/Bid | 投标信息、售前方案、报价、评审 | 售前承诺超能力、报价低于成本 |
| 售前→实施 | 合同 Contract | 交付范围、里程碑付款、验收条款、SLA | 范围模糊、验收标准缺失 |
| 实施 | 项目计划 Plan | 里程碑、任务、依赖、资源 | 计划不合理、依赖未识别 |
| 实施 | 项目进度 Progress | 实际 vs 计划偏差、延期、阻塞 | 里程碑延期、偏差超阈值 |
| 实施 | 需求分析 Requirement | 需求清单、优先级、变更、确认 | 需求蔓延、需求未确认 |
| 实施 | 方案 Solution | 产品方案、技术方案、评审状态 | 方案未评审、技术不成熟 |
| 实施 | 风险点 Risk | 风险登记、等级、概率、影响、缓解 | 风险未跟踪、缓解未落实 |
| 运维质保 | 运维事件/工单 Ops | 质保期问题、SLA 履行、工单 | SLA 违约、质保期内反复返工 |

### 1.3 业务价值

1. **自动识别风险**：从合同内容、项目范围、功能清单、产品原型、技术方案五类输入中自动识别风险信号。
2. **全链路关联**：售前承诺 → 合同 → 需求 → 方案 → 进度 → 运维，风险沿链路传导可追踪。
3. **双角色视角**：项目经理管单项目细节，项目总监看跨项目风险总览。
4. **提高质量与成功率**：风险前置暴露、缓解措施可跟踪、决策有据可查。
5. **沉淀组织资产**：本体模型是行业知识资产，可复用、可演进。

## 2. 核心设计理念：为什么用"本体"

| 对比项 | 传统项目管理软件 | 本体驱动方案 |
|---|---|---|
| 数据组织 | 各模块孤立表单 | 统一语义模型：类 + 属性 + 关系 |
| 跨模块查询 | JOIN / 硬编码 | 语义推理 + 图查询 |
| 风险识别 | 人工登记为主 | 文档要素抽取 + 规则匹配 + LLM 辅助 |
| 扩展性 | 加字段要改库 | 本体演进，加类/加关系即可 |

## 3. 领域本体建模草案（全链路版）

### 3.1 核心类（Class，已落地 15 个）

```
售前阶段
├── 商机 (Bid)                  # 项目名称、客户、售前方案、报价、评审状态、投标状态
实施阶段
├── 合同 (Contract)             # 合同编号、金额、签订日期、交付范围、验收条款、里程碑付款
├── 项目 (Project)              # 项目编号、名称、客户、实施周期、项目经理、状态
├── 计划 (Plan)                 # 里程碑(Milestone)、任务(Task)、依赖、负责人、计划起止
├── 进度 (Progress)             # 实际起止、进度百分比、偏差天数、状态
├── 需求 (Requirement)          # 需求编号、优先级、状态、来源、变更次数、确认状态
├── 方案 (Solution)             # 产品方案、技术方案、评审状态
├── 风险 (Risk)                 # 风险类型、等级、概率、影响、缓解措施、状态
运维质保阶段
├── 运维事件 (OpsEvent)         # 工单编号、问题描述、SLA 状态、响应/解决时长、状态
├── SLA (Sla)                   # 响应时限、解决时限、违约条款
├── 质保期 (Warranty)           # 起止日期、覆盖范围
通用
├── 干系人 (Stakeholder)        # 客户方、我方；角色（项目经理/项目总监/需求/开发/实施/QA）
├── 文档 (Document)             # 合同文本、项目范围、功能清单、产品原型、技术方案、会议纪要
```

### 3.2 核心关系（Object Property，已落地 16 条）

```
Bid --中标形成--> Contract            (商机中标形成合同)
Contract --约束--> Project            (合同约束项目范围)
Project --包含--> Plan                (项目包含计划)
Plan --包含--> Milestone/Task         (计划包含里程碑/任务)
Requirement --来源于--> Contract      (需求来源于合同条款)
Solution --实现--> Requirement        (方案实现需求)
Solution --引入--> Risk               (技术方案引入技术风险)
Requirement --变更导致--> Risk        (需求变更导致范围风险)
Milestone --延期导致--> Risk          (里程碑延期导致进度风险)
Progress --偏差--> Risk               (进度偏差触发风险)
Risk --影响--> Milestone              (风险影响里程碑)
Project --进入--> OpsEvent            (项目进入运维质保产生事件)
Sla --约束--> OpsEvent                (SLA 约束运维事件处理)
Document --描述--> Contract/Requirement/Solution   (文档描述各业务对象)
Stakeholder --负责--> Task/Risk       (干系人负责任务/风险)
```

### 3.3 关键数据属性（Data Property，已落地 18 个）

- 进度：`progress_percent`、`delay_days`、`is_blocked`
- 需求：`change_count`、`is_confirmed`、`priority`
- 合同：`has_acceptance_clause`、`payment_milestones`、`scope_text`（项目范围文本）
- 功能清单：`feature_count`、`has_priority`、`features_text`
- 产品原型：`prototype_url`、`is_reviewed`、`prototype_desc`
- 技术方案：`tech_stack`、`is_reviewed`、`has_unresolved_items`
- 风险：`probability`、`impact`、`severity`、`mitigation_status`
- 运维：`sla_status`、`response_hours`、`resolution_hours`

## 4. 风险自动识别机制（本工具的灵魂）

> 已确认：根据 **合同内容 / 项目范围 / 功能清单 / 产品原型 / 技术方案** 自动识别，规则为主 + LLM 辅助。

### 4.1 识别输入 → 风险示例（预置识别规则）

| 输入文档 | 关键要素 | 可识别的风险 |
|---|---|---|
| 合同内容 | 验收条款缺失 / 范围描述模糊 / 付款节点不合理 | 验收风险、范围风险、回款风险 |
| 项目范围 | 范围过大 / 未定义边界 / 与合同不一致 | 范围蔓延风险、交付延期风险 |
| 功能清单 | 功能点过多 / 无优先级 / 无验收标准 | 交付质量风险、需求确认风险 |
| 产品原型 | 未评审 / 与合同范围不符 / 变更频繁 | 需求确认风险、范围超合同风险 |
| 技术方案 | 新技术栈 / 未评审 / 存在未决项 | 技术风险、实施延期风险 |

### 4.2 自动识别流水线（MVP 可执行版）

```
① 文档录入/导入（手工录入文本 或 上传导入）
   ↓
② 要素抽取（内置抽取规则：关键词/结构化字段对照；LLM 可选增强）
   ↓
③ 规则匹配（预置规则 L1：如"验收条款缺失"→ 验收风险）
   ↓
④ 关系推演（L2：沿本体关系传导，如 合同风险 → 需求 → 方案 → 进度）
   ↓
⑤ 风险落库（生成风险记录，标记"自动识别"，等级由概率×影响计算）
   ↓
⑥ 人工确认（项目经理/总监 确认或驳回，LLM 输出仅作建议）
```

### 4.3 四层识别架构（L1-L4）

| 层级 | 机制 | 说明 | 示例 |
|---|---|---|---|
| L1 规则引擎 | 确定性规则 | 基于要素/属性触发 | 验收条款缺失 → 验收风险 |
| L2 关系推演 | 推理传播 | 沿本体关系传导 | 合同范围风险 → 影响进度 |
| L3 数据信号 | 阈值/偏差检测 | 进度/需求数据异常 | 进度偏差 > 20% → 预警 |
| L4 LLM 辅助 | 大模型分析（可插拔） | 从非结构化文本识别 | 合同条款扫描、需求描述分析 |

### 4.4 预置规则示例（可视化可配置）

```
规则1 [验收风险]   IF contract.has_acceptance_clause = FALSE       THEN 创建"验收标准缺失"风险
规则2 [范围风险]   IF requirement.change_count > 3                  THEN 创建"需求蔓延"风险
规则3 [交付风险]   IF feature_list.feature_count > 50 AND no_priority THEN 创建"功能清单过大"风险
规则4 [技术风险]   IF solution.review_status != "已评审"             THEN 创建"方案未评审"风险
规则5 [技术风险]   IF solution.tech_stack 含 未用过/新技术           THEN 创建"技术不成熟"风险
规则6 [里程碑]     IF milestone.delay_days > 7                      THEN 创建"里程碑延期"风险
规则7 [SLA风险]    IF ops_event.sla_status = "即将违约"              THEN 创建"SLA 违约"风险
规则8 [联动升级]   IF 同一风险影响 ≥ 2 个里程碑                      THEN 风险等级上调一级
```

### 4.5 风险量化

```
风险等级 = f(概率 probability, 影响 impact)
红(高) / 黄(中) / 绿(低)  三级展示，支持看板聚合
```

## 9. 风险与不确定性

| 风险 | 应对 |
|---|---|
| 本体建模过度设计 | 先建最小可用本体（MVP 核心类 ≤ 12 个），快速迭代 |
| 自动识别准确率 | 预置规则先保证基础覆盖；识别结果一律经人工确认 |
| LLM 结果不可控 | LLM 仅输出"建议"，落库必须经规则或人工确认 |
| node:sqlite 实验性 API 变化 | 已实测 Node 22.22.2 可用；如升级 Node 注意兼容 |
| 用户录入负担 | 模板化录入 + Excel 导入 + 文档粘贴式录入 |
