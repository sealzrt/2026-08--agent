### 1.3 写作质量检查清单

每章完成后，对照以下清单逐项检查：

| # | 检查项 | 标准 |
|---|--------|------|
| Q1 | 每个概念都有"为什么" | 没有任何概念是以纯定义开头的 |
| Q2 | 每个术语都有类比 | 类比库中的类比已被使用或扩展 |
| Q3 | 贯穿案例已更新 | 旅行助手在本章有对应版本演进 |
| Q4 | 章间桥接完整 | 结尾三句话（成果→缺陷→预告）齐全 |
| Q5 | 三层深度标记正确 | 第二层有 🔧 标记，第三层有 📂 链接 |
| Q6 | 动手实践可运行 | 代码复制粘贴可直接执行，无缺失依赖 |
| Q7 | 常见坑已填写 | 至少 1 个坑，含现象/原因/解决 |
| Q8 | 概念依赖无跳跃 | 正文中未出现"尚未定义"的术语 |
| Q9 | 路径标注正确 | 每节都标注了 🔵/🟢/📖 |
| Q10 | 字数在范围内 | 认知篇 6000-10000 字/章，构建篇 10000-15000 字/章 |
| Q11 | 代码片段 ≤30 行 | 正文中的代码不超过 30 行，完整版在仓库 |
| Q12 | 习题覆盖三个层次 | 概念题×2 + 动手题×2 + 开放题×1 |

### 1.4 贯穿案例设计规范

旅行助手在每章的版本演进必须满足：

| 规则 | 说明 |
|------|------|
| **代码可叠加** | 每章的新代码是在上一章代码基础上增加，不是重写 |
| **可独立运行** | 每章的代码都可以独立运行，不依赖后续章节的代码 |
| **效果可感知** | 每次升级后，用户能直观感受到"新功能做了什么" |
| **版本号明确** | 代码中标注 `v0.X`，与章节对应 |

### 1.5 类比使用规范

| 规则 | 说明 |
|------|------|
| 首次引入必须类比 | 任何技术概念首次出现时，必须配日常类比 |
| 后续引用可省略 | 已定义过的类比，后续章节只需提概念名 |
| 类比可回引 | 后续章节可引用前面的类比，如"还记得'开卷考试'吗？" |
| 类比库持续积累 | 每章新增的类比要追加到全局类比库 |

**3.2 Transformer 四步拆解详细设计**：

```
3.2.1 为什么需要注意力？（400 字）
  问题：长句子"昨天我去了北京，在那里吃了一种叫做驴打滚的小吃"
       → "那里"指的是"北京"，RNN 很难捕捉这种远距离依赖
  类比：100 人开会，你不可能记住每个人说的话，
       你会选择性关注——注意力机制就是让模型学会"关注谁"

3.2.2 Self-Attention 的直觉（500 字）
  类比：开会时你听每个人发言，给每个人打一个"相关度分数"，
       然后根据分数加权综合所有人的观点
  图示：Query-Key-Value 的直觉图（不用公式）
  
3.2.3 从注意力到 Transformer（400 字）
  组件拼图：多头注意力 + 前馈网络 + 残差连接 + 层归一化
  图示：完整 Transformer 架构图（简化版）
  
3.2.4 Decoder-Only：为什么 ChatGPT 只用了一半？（400 字）
  Encoder-Decoder vs Decoder-Only 的区别
  为什么生成式任务只需要 Decoder
  类比：翻译需要"先理解再输出"（双脑），
       聊天只需要"边想边说"（单脑）
```

**动手实践设计**：
- **实验 1**：同一个 prompt，分别设置 Temperature=0/0.7/1.5，对比输出
- **实验 2**：让 LLM 回答"中国有多少人口？"（事实题）和"人生的意义是什么？"（开放题），对比幻觉表现
- **常见坑**：Temperature=0 时输出仍有微小随机性 → 设置 seed 参数

**章间桥接**：
- 📦 成果：你理解了 LLM 的工作原理，能调节参数控制输出质量
- ⚠️ 缺陷：LLM 只能生成文本，它不知道今天的天气、不能查航班
- ➡️ 预告：Ch4 将给 LLM 装上"手和眼"——工具调用
