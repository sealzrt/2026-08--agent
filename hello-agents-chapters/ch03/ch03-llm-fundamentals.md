## 3.1 语言模型演进：从 N-gram 到 Transformer

### 一个简单的问题：如何预测下一个词？

"今天天气真"—— 你的大脑会自动预测下一个词可能是"好""热""冷"。

**语言模型**就是做这件事的程序。不同时代的语言模型，用不同的方法来预测：

| 时代 | 方法 | 原理 | 局限 |
|------|------|------|------|
| 1950s | N-gram | 统计"前面 N 个词"出现的频率 | 只能看前 2-3 个词，更远的看不到 |
| 1990s | RNN/LSTM | 用"隐藏状态"传递上下文信息 | 句子太长时，前面的信息会被"遗忘" |
| 2017 | Transformer | 用"注意力"同时关注所有词 | 计算量大，但效果远超之前的方法 |

> 💡 **类比**：N-gram 像是只看眼前两步棋；RNN 像是能记住之前走过的路，但走着走着就忘了起点；Transformer 像是站在高处俯瞰全局，同时看到所有走过的路。

## 3.2 Transformer 核心机制（四步拆解）

这是本书**最需要耐心**的一节。我们会把它拆成 4 个小步骤，每个步骤只讲一件事。

### 3.2.1 为什么需要"注意力"？

想象这个句子：

> "昨天我去了**北京**，在那里吃了一碗炸酱面，然后去故宫参观了清明上河图，**那里**的导游讲了很多有趣的故事。"

"那里"指的是什么？答案是"北京"。但"北京"在句子的开头，"那里"在句子的末尾——它们之间隔了 30 多个字。

RNN 的问题：它像接力赛一样，信息从第一个词传到最后一个词。传着传着，最早的信息就"衰减"了。

**注意力机制**的想法：不搞接力赛了。让每个词都能**直接看到**所有其他词，然后自己决定"我应该关注谁"。

> 💡 **类比**：100 人开会。RNN 的方式是每个人只听旁边的人说什么，然后传话给下一个（传话游戏，传到最后肯定走样）。注意力的方式是每个人都能听到所有人发言，然后选择性地关注最相关的几个人。

### 3.2.2 Self-Attention 的直觉

Self-Attention 的核心思想可以用一个会议场景来理解：

1. 每个人（每个词）发出三个信号：
   - **Query**（我在找什么信息？）
   - **Key**（我能提供什么信息？）
   - **Value**（我实际要说的内容）

2. 每个人用自己的 Query 去和所有人的 Key 做匹配，算出一个"相关度分数"

3. 根据分数，加权综合所有人的 Value，得到最终的"综合观点"

```
例子："猫 坐 在 垫子 上 因为 它 很 舒服"
                                           ↑
                                        "它"指什么？

"它" 的 Query："我在找什么？→ 我在找我是谁"
"猫" 的 Key  → "我能提供：我是一个动物"
"垫子"的 Key → "我能提供：我是一个物品"

"它"和"猫"的相关度分数高 → "它"大概率指"猫"
```

> 💡 这就是 Self-Attention 的全部直觉：**每个词发出查询，和所有词匹配，然后综合最相关的信息。** 没有更多了。

### 3.2.3 从注意力到完整的 Transformer

把 Self-Attention 和其他组件拼在一起，就是完整的 Transformer：

```
输入文本
   ↓
[词嵌入] 把每个词变成一组数字（向量）
   ↓
[位置编码] 告诉模型每个词在句子中的位置
   ↓
[Transformer 层 × N] 每一层包含：
   ├── 多头注意力：从多个角度（语义、语法、指代...）做注意力
   ├── 前馈网络：对每个词做非线性变换
   ├── 残差连接：保留原始信息，防止"忘本"
   └── 层归一化：稳定训练过程
   ↓
[输出层] 预测下一个词的概率
```

> 💡 **类比**：Transformer 像一个精密的工厂流水线。词嵌入是"原材料加工"，位置编码是"编号排序"，注意力层是"工人协作讨论"，前馈网络是"个人深度加工"。

### 3.2.4 Decoder-Only：为什么 ChatGPT 只用了一半？

原始 Transformer 有两个部分：
- **Encoder**：理解输入（"阅读"）
- **Decoder**：生成输出（"写作"）

但 GPT 系列只用 Decoder。为什么？

| 架构 | 适用任务 | 代表模型 |
|------|---------|---------|
| Encoder-Only | 理解任务（分类、检索） | BERT |
| Decoder-Only | 生成任务（对话、写作） | GPT、Claude |
| Encoder-Decoder | 转换任务（翻译） | T5 |

> 💡 **类比**：Encoder-Decoder 像翻译官——先完整理解原文（Encoder），再翻译成另一种语言（Decoder）。Decoder-Only 像即兴演讲者——边想边说，每个词基于前面所有词生成。ChatGPT 的工作方式更像后者。

## 3.3 与 LLM 对话：提示工程

### 你和 LLM 对话的方式，决定了它回答的质量

同一个 LLM，不同的提问方式，结果天差地别：

```
❌ 差的提问："告诉我关于上海的事"
   → 返回一堆笼统的百科知识

✅ 好的提问："我要在上海玩3天，预算5000元，
            喜欢历史和美食。请给我一份日程安排，
            包含交通方式和预估费用。"
   → 返回详细、个性化的行程规划
```

### 四种核心提示技巧

| 技巧 | 原理 | 示例 |
|------|------|------|
| **角色设定** | 给 LLM 一个"身份"，约束其回复风格 | "你是一位资深旅行顾问" |
| **Few-shot** | 给几个例子，让 LLM 学会你想要的格式 | "示例1：... 示例2：... 现在请做第3个" |
| **Chain-of-Thought** | 要求 LLM "一步步想" | "请逐步分析这个行程的可行性" |
| **结构化输出** | 指定输出格式 | "请以 JSON 格式返回" |

### 控制输出质量的关键参数

| 参数 | 含义 | 推荐值 |
|------|------|--------|
| **Temperature** | 控制随机性。0=确定性，2=极度随机 | 任务型：0-0.3；创意型：0.7-1.0 |
| **Top-p** | 只从概率前 p% 的词中采样 | 通常 0.9 |
| **Max tokens** | 最大输出长度 | 根据任务设定 |

## 3.4 文本分词与模型调用实操

### Tokenization：LLM 看到的不是一样的文字

当你输入"今天天气真好"时，LLM 看到的不是 5 个汉字，而是一串数字（Token ID）：

```
"今天天气真好" → [12680, 2399, 2399, 3389, 1974]
                  ↑    ↑    ↑    ↑    ↑
                 今天  天   气   真   好
```

不同的分词器（Tokenizer）切分方式不同：
- 有些模型把"今天"切成一个 Token
- 有些把"今"和"天"切成两个 Token

> 💡 **为什么这很重要？** Token 数量决定了你的 API 费用和处理速度。同样的文本，不同模型的 Token 数可能差 2-3 倍。

### 调用 API 实操

```python
# --- 导入依赖 ---
from openai import OpenAI          # DeepSeek 兼容 OpenAI SDK，所以用 openai 包
import os
from dotenv import load_dotenv     # 从 .env 文件加载环境变量（避免把 API Key 写在代码里）

# --- 初始化 DeepSeek 客户端 ---
# 从 .env 文件加载 DEEPSEEK_API_KEY 等环境变量
load_dotenv()

# DeepSeek 兼容 OpenAI 协议，只需把 base_url 指向 DeepSeek 的服务地址
deepseek_client = OpenAI(
    base_url="https://api.deepseek.com",      # DeepSeek API 地址（替代 OpenAI 默认地址）
    api_key=os.getenv("DEEPSEEK_API_KEY"),    # 从环境变量读取 API Key，不要硬编码
)

# --- 基础调用示例 ---
response = deepseek_client.chat.completions.create(
    model="deepseek-chat",         # DeepSeek 对话模型
    messages=[
        {"role": "system", "content": "你是一个旅行助手"},  # 系统角色设定
        {"role": "user", "content": "推荐3个上海景点"}   # 用户输入
    ],
    temperature=0.7,               # 控制随机性：0=确定，1=随机
    max_tokens=500,                # 限制最大输出 Token 数
)

# 提取并打印模型的文本回复
print(response.choices[0].message.content)
# 查看本次调用消耗的 Token 数（用于计算成本）
print(f"消耗 Token: {response.usage.total_tokens}")
```

## 3.5 LLM 的能力与局限

### LLM 能做什么？

- 理解和生成自然语言
- 代码编写和调试
- 逻辑推理（有限）
- 翻译、摘要、改写
- 少样本学习（给几个例子就能学会新任务）

### LLM 不能做什么？（三大局限）

**1. 幻觉（Hallucination）**

```
问："鲁迅和周树人是什么关系？"
LLM 可能回答："鲁迅和周树人是同时代的两位文学家..."
（事实上鲁迅就是周树人的笔名，他们是同一个人）
```

LLM 不是在"查数据库"，而是在"预测最可能的下一个词"。当它不确定时，会"编造"看起来合理但实际错误的信息。

**2. 无法获取实时信息**

LLM 的知识有截止日期（训练数据的时间点）。它不知道今天的天气、最新的新闻、你的公司内部信息。

**3. 推理能力有限**

```
问："257 × 389 = ?"
LLM 很可能算错。因为它不是在做数学运算，而是在"预测看起来像答案的数字"。
```

> 💡 **这三个局限正是后续章节的动机**：
> - 局限 1 → Ch15 安全与对齐（防御幻觉）
> - 局限 2 → Ch4 工具调用（让 LLM 能查实时信息）
> - 局限 3 → Ch5 思维范式（让 LLM 更结构化地推理）

## 动手实践

### 🎯 实验：Temperature 对输出的影响

```python
# 对比不同 Temperature 值对输出的影响
for temp in [0, 0.7, 1.5]:
    response = deepseek_client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": "给我推荐一个旅游目的地"}],
        temperature=temp,          # 每次用不同的温度值
    )
    # 只截取前 80 个字符，方便对比差异
    print(f"[Temperature={temp}] {response.choices[0].message.content[:80]}")
```

运行 3 次，观察：
- Temperature=0：每次几乎相同
- Temperature=0.7：有变化但合理
- Temperature=1.5：可能出现奇怪的推荐

### 🎯 实验：幻觉检测

```python
# 准备测试题：覆盖事实类、开放类、数学类，检测幻觉倾向
questions = [
    "中国有多少人口？",           # 事实题：有确定答案
    "爱因斯坦是哪年出生的？",      # 事实题：容易验证真伪
    "人生的意义是什么？",          # 开放题：无标准答案
    "257 × 389 = ?",             # 数学题：LLM 容易算错
]
for q in questions:
    resp = deepseek_client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": q}],
        temperature=0,             # 用最低温度，尽量确定性输出
    )
    print(f"Q: {q}\nA: {resp.choices[0].message.content}\n")
```

### 🚧 常见坑

**坑 #1：Temperature=0 并不完全确定性**
- 现象：即使 Temperature=0，多次调用仍可能出现微小差异
- 原因：浮点运算的非确定性
- 解决：需要完全确定性时，配合 `seed` 参数使用

**坑 #2：Token 数 ≠ 字数**
- 现象：以为 500 个 Token 能输出 500 个字，结果只输出了 200 个
- 原因：中文通常 1 个字 ≈ 1-2 个 Token
- 解决：预留 2 倍余量

### 🗂 知识卡片

| 概念 | 一句话解释 | 类比 |
|------|-----------|------|
| Transformer | 基于注意力机制的神经网络架构 | 精密工厂流水线 |
| Self-Attention | 每个词直接关注所有相关词 | 开会时选择性关注发言者 |
| Token | LLM 处理文本的最小单位 | 文字被切成的"碎片" |
| 提示工程 | 通过精心设计输入来优化输出 | 和实习生沟通的技巧 |
| 幻觉 | LLM 编造看似合理但错误的信息 | 不懂装懂的人 |

### ⚠️ 还缺什么？

LLM 能理解和生成文本，但它**无法与外部世界交互**。它不知道今天的天气、查不了航班、订不了酒店。它就像一个博学但被关在房间里的人。
