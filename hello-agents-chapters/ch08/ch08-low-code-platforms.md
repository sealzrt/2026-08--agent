## 8.1 为什么需要低代码平台？

### 代码开发 vs 低代码平台

| 维度 | 代码开发 | 低代码平台 |
|------|---------|-----------|
| 速度 | 慢（需要写代码、调试） | 快（拖拽配置） |
| 灵活性 | 高（任意定制） | 中（受平台限制） |
| 学习曲线 | 需要编程基础 | 几乎零门槛 |
| 适用人群 | 开发者 | 产品经理、运营、所有人 |
| 生产就绪 | 需要自己做 | 平台提供部署和监控 |

---

## 8.2 Coze：字节跳动的智能体平台

### 核心功能

- **Bot 创建**：通过对话式界面定义智能体的角色和能力
- **插件市场**：内置大量第三方工具（搜索、地图、天气等）
- **工作流编排**：可视化编排多步骤流程
- **知识库**：上传文档构建 RAG

### 快速实战：创建"每日 AI 简报"助手

1. 登录 coze.cn，创建新 Bot
2. 设置系统提示词："你是一个 AI 新闻编辑，每天整理最新的 AI 领域新闻"
3. 添加"搜索"插件
4. 添加"定时触发"工作流
5. 测试并部署

---

## 8.3 Dify：开源 LLMOps 平台

### 核心特点

- **开源免费**：可以自托管
- **工作流编排**：强大的可视化工作流
- **多模型支持**：DeepSeek、OpenAI、Claude、本地模型都能用
- **API 优先**：每个应用都自动生成 API

### 快速实战：创建个人智能助手

1. 部署 Dify（Docker 一键部署）
2. 创建"聊天助手"应用
3. 配置 LLM（选择模型、设置 Temperature）
4. 上传知识库文档
5. 测试对话效果

---

## 8.4 FastGPT 与 n8n

### FastGPT

专注于**知识库驱动**的智能体：
- 优势：文档管理能力强，支持多种文档格式
- 适合：企业内部知识问答、客服机器人

### n8n

专注于**工作流自动化**：
- 优势：400+ 内置集成（邮件、Slack、数据库...）
- 适合：自动化重复任务、多系统数据流转

## 8.5 平台选型决策矩阵

| 维度 | Coze | Dify | FastGPT | n8n |
|------|------|------|---------|-----|
| 上手难度 | ⭐ 最简单 | ⭐⭐ | ⭐⭐ | ⭐⭐⭐ |
| 灵活性 | ⭐⭐ | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ |
| 知识库 | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ |
| 工作流 | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐⭐ |
| 自托管 | ❌ | ✅ | ✅ | ✅ |
| 费用 | 免费+付费 | 开源免费 | 开源免费 | 开源免费 |

**选择建议**：
- 想最快出原型 → Coze
- 想自托管 + 灵活定制 → Dify
- 以文档问答为主 → FastGPT
- 需要自动化工作流 → n8n

## 8.6 低代码与代码开发的融合

### 什么时候该迁移到代码？

| 信号 | 说明 |
|------|------|
| 平台功能不够用 | 需要自定义逻辑但平台不支持 |
| 性能要求高 | 平台响应速度无法满足 |
| 需要集成自有系统 | 平台无法连接你的内部 API |
| 团队协作需求 | 需要版本控制和代码审查 |

### 渐进式迁移策略

```
阶段 1：纯低代码（验证想法）
阶段 2：低代码 + API 扩展（添加自定义逻辑）
阶段 3：代码为主 + 低代码辅助（复杂功能代码化，简单流程保持低代码）
```

## 动手实践

### 🎯 在 Coze 上构建一个旅行助手

1. 创建 Bot，设置角色为"旅行顾问"
2. 添加天气查询和地图搜索插件
3. 上传一份旅行攻略作为知识库
4. 测试对话效果

### 🚧 常见坑

**坑 #1：平台锁定**
- 现象：在 Coze 上构建的智能体无法迁移到其他平台
- 解决：尽量用通用标准（如 OpenAPI）定义工具，保留可迁移性

### 🏋️ 进阶挑战

用 Dify 构建一个工作流：用户输入目的地 → 查天气 → 搜酒店 → 生成行程报告 → 发送邮件。
