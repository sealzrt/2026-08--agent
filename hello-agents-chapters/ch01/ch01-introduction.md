## 1.1 什么是智能体？

### 从一个场景开始

想象你有一个实习生，你给他一个任务："帮我规划下周三人的团建活动"。

这个实习生会怎么做？

1. **理解任务**：团建，3人，下周三
2. **思考方案**：可能需要查场地、问大家的时间偏好、比较价格
3. **采取行动**：打电话给餐厅预订、发邮件询问同事时间
4. **汇报结果**：整理好方案，向你汇报
5. **接受反馈**：你说"太贵了"，他重新找更便宜的方案

这个实习生就是一个**智能体**——他能感知环境（你的指令）、自主思考（规划方案）、采取行动（打电话、发邮件），并根据反馈调整行为。

### 正式定义

**智能体（Agent）** 是一个能够感知环境、做出决策并采取行动以实现目标的自主系统。

在 AI 领域，现代智能体通常以**大语言模型（LLM）** 作为"大脑"，辅以工具调用、记忆系统等能力，来完成复杂任务。

### PEAS 模型：判断一个系统是否是智能体

要判断一个 AI 应用是否属于智能体，可以用 **PEAS 模型**来分析：

| 维度 | 含义 | 旅行助手示例 |
|------|------|-------------|
| **P**erformance（性能指标） | 怎么衡量它做得好不好？ | 行程合理性、用户满意度 |
| **E**nvironment（环境） | 它在什么环境中运作？ | 用户对话、天气API、地图API |
| **A**ctuators（执行器） | 它能做什么动作？ | 回复文本、调用API、存储信息 |
| **S**ensors（传感器） | 它能感知什么信息？ | 用户输入、API返回结果 |

如果一个系统四个维度都有明确定义，它就是一个智能体。如果一个系统只是"输入→输出"的简单映射（比如关键词回复机器人），那它更接近一个工具，而非智能体。

### 智能体的三种类型

| 类型 | 特征 | 典型例子 |
|------|------|---------|
| **工具型** | 用户发起指令，智能体执行特定操作 | GitHub Copilot、代码审查工具 |
| **对话型** | 通过持续对话完成任务 | 客服机器人、旅行助手 |
| **自主型** | 自主设定子目标，长期运行 | 自动化运维、研究助手 |

> 💡 这三种类型不是非此即彼的，而是一个**自主性光谱**。工具型在最左端（人类主导），自主型在最右端（智能体主导），对话型在中间。

## 1.2 智能体 vs 工作流 vs RAG

在 AI 应用开发中，有三种常见的架构范式。理解它们的区别，能帮你选择正确的技术路线。

### 三种架构对比

```
┌─────────────────────────────────────────────────────────────┐
│  工作流（Workflow）                                          │
│  ┌────┐    ┌────┐    ┌────┐    ┌────┐                      │
│  │ 步骤1 │──→│ 步骤2 │──→│ 步骤3 │──→│ 结果 │              │
│  └────┘    └────┘    └────┘    └────┘                      │
│  特点：路径固定，每步预定义，像流水线                          │
├─────────────────────────────────────────────────────────────┤
│  RAG（检索增强生成）                                         │
│  ┌──────┐    ┌────┐    ┌────────┐                          │
│  │ 用户问 │──→│ 检索 │──→│ LLM 回答 │                      │
│  └──────┘    └────┘    └────────┘                          │
│  特点：先查资料再回答，像开卷考试                              │
├─────────────────────────────────────────────────────────────┤
│  智能体（Agent）                                             │
│  ┌──────┐    ┌────┐    ┌────┐    ┌────┐                   │
│  │ 用户问 │──→│ 思考 │←→│ 工具 │←→│ 行动 │──→ 循环直到完成  │
│  └──────┘    └────┘    └────┘    └────┘                   │
│  特点：自主决策，动态调用工具，像真人助手                      │
└─────────────────────────────────────────────────────────────┘
```

### 什么时候该选哪种？

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| "每天定时汇总新闻" | 工作流 | 步骤固定，不需要决策 |
| "回答公司制度问题" | RAG | 需要从文档中检索答案 |
| "帮我规划并预订一次旅行" | 智能体 | 需要多步决策和工具调用 |
| "自动修复代码 bug" | 智能体 | 需要分析、尝试、验证的循环 |

> 💡 **关键区别**：工作流是"你告诉它怎么做"，智能体是"你告诉它做什么"。智能体自己决定执行路径。

## 1.3 5 分钟体验你的第一个智能体

理论说够了，让我们动手。接下来你将运行一个真实的智能体程序。

### 准备工作

你需要：
- Python 3.10+
- 一个 LLM API Key（推荐 DeepSeek，也兼容 OpenAI）

```bash
# 安装依赖
pip install openai python-dotenv

# 创建环境变量文件
echo "DEEPSEEK_API_KEY=your-key-here" > .env
```

### 最小智能体代码

```python
# --- 导入依赖 ---
from openai import OpenAI          # DeepSeek 兼容 OpenAI SDK，所以用 openai 包
from dotenv import load_dotenv     # 从 .env 文件加载环境变量（避免把 API Key 写在代码里）
import os

# --- 初始化 DeepSeek 客户端 ---
# 从 .env 文件加载 DEEPSEEK_API_KEY 等环境变量
load_dotenv()

# DeepSeek 兼容 OpenAI 协议，只需把 base_url 指向 DeepSeek 的服务地址
deepseek_client = OpenAI(
    base_url="https://api.deepseek.com",      # DeepSeek API 地址（替代 OpenAI 默认地址）
    api_key=os.getenv("DEEPSEEK_API_KEY"),    # 从环境变量读取 API Key，不要硬编码
)

# --- 定义最小智能体函数 ---
def chat(user_message: str, history: list = None) -> str:
    """最简智能体：接收用户消息，返回 LLM 回复。

    参数:
        user_message: 用户当前输入的文本
        history: 之前的对话历史（可选，用于多轮对话）
    返回:
        LLM 生成的回复文本
    """
    # 构造消息列表，system 消息定义 Agent 的角色和行为风格
    messages = [
        {"role": "system", "content": "你是一个友好的旅行助手。"},
    ]
    # 如果有历史对话，拼接到消息列表中（实现多轮对话记忆）
    if history:
        messages.extend(history)
    # 将用户当前消息追加到末尾（模型最后看到的就是这条）
    messages.append({"role": "user", "content": user_message})

    # 调用 DeepSeek API 生成回复
    response = deepseek_client.chat.completions.create(
        model="deepseek-chat",     # DeepSeek-V3 对话模型
        messages=messages,         # 完整的消息列表（system + history + user）
    )
    # 提取模型的文本回复并返回
    return response.choices[0].message.content

# --- 运行测试：发一条消息给旅行助手 ---
print(chat("我想去上海玩三天，帮我推荐景点"))
```

### 运行它

```bash
python main.py
```

你会看到 LLM 返回一个上海三日游的推荐列表。这就是你的**旅行助手 v0.1**——它能对话，但还不能查实时信息、不能预订酒店。后续章节中，我们会逐步为它添加工具调用、记忆、规划等能力。

## 1.4 智能体的构成与运行原理

你刚才运行的程序虽然简单，但已经包含了智能体的核心结构。让我们把它拆开看看。

### Agent 循环：感知→思考→行动

每个智能体都在重复同一个循环：

```
        ┌─────────┐
        │  感知    │ ← 接收用户输入、API 返回、环境变化
        └────┬────┘
             ↓
        ┌─────────┐
        │  思考    │ ← LLM 分析当前状态，决定下一步
        └────┬────┘
             ↓
        ┌─────────┐
        │  行动    │ ← 调用工具、回复用户、存储信息
        └────┬────┘
             ↓
        （循环，直到任务完成）
```

这个循环叫做 **Agent Loop**，它是所有智能体系统的核心。

> 💡 类比：你在做饭时的思维循环——看食谱（感知）→ 判断下一步该做什么（思考）→ 切菜/炒菜（行动）→ 再看食谱（感知）...直到菜做好。

### 智能体的四大组件

| 组件 | 作用 | 在 v0.1 中对应 |
|------|------|---------------|
| **大脑（LLM）** | 理解输入、推理决策 | `deepseek_client.chat.completions.create()` |
| **感知（Input）** | 接收外部信息 | `user_message` 参数 |
| **行动（Tools）** | 与外部世界交互 | v0.1 还没有工具（只能回复文本） |
| **记忆（Memory）** | 保存历史信息 | v0.1 还没有记忆（每次对话独立） |

当前的 v0.1 只有"大脑"和"感知"，缺少"行动工具"和"记忆"。这正是后续章节要补上的两块拼图。

## 动手实践

### 🎯 最小可运行示例

上面的 v0.1 代码就是本章的实践。确保你能成功运行它。

### 🚧 常见坑

**坑 #1：API Key 泄露**
- 现象：把 API Key 写在代码里，推送到 GitHub 后被盗用
- 原因：Key 是明文的，任何人都能看到
- 解决：使用 `.env` 文件 + `python-dotenv`，永远不要把 `.env` 加入 Git

**坑 #2：中文乱码**
- 现象：Windows 终端输出中文显示乱码
- 原因：终端编码不是 UTF-8
- 解决：执行 `chcp 65001` 或在代码开头添加 `# -*- coding: utf-8 -*-`

### 🏋️ 进阶挑战

修改 v0.1 的系统提示词，尝试以下三种角色设定，观察回复风格的变化：
1. "你是一个幽默风趣的旅行达人，回答时多用 emoji 和口语化表达"
2. "你是一个专业的旅行社顾问，回答时给出详细的数据和费用"
3. "你是一个极简主义者，回答不超过 50 个字"

思考：**系统提示词就是智能体的"性格"**。同一个 LLM，不同的提示词，表现截然不同。

## 本章小结

### 📦 本章成果

你构建了**旅行助手 v0.1**——它能理解你的输入并生成回复，但它还不会查天气、搜酒店（没有工具），也不记得你上次说的话（没有记忆）。

### 🗂 知识卡片

| 概念 | 一句话解释 | 类比 |
|------|-----------|------|
| 智能体 | 能感知、思考、行动的自主系统 | 实习生 |
| PEAS 模型 | 分析智能体的四个维度 | — |
| Agent Loop | 感知→思考→行动的循环 | 做饭时的思维过程 |
| 工作流 vs Agent | 固定路径 vs 自主决策 | 流水线 vs 真人助手 |

### ⚠️ 还缺什么？

我们的旅行助手只能"说话"。它不知道今天天气如何、不能查询航班信息、无法访问任何外部数据。它就像一个博学但被关在房间里的人——知道很多，但获取不到实时信息。
