## Phase 1：认知篇撰写（Ch1-5，10 天）

### 核心原则
认知篇是读者的"第一印象"。如果前 5 章不能让读者觉得"这门课讲得清楚"，后面的内容写得再好也没人读到。

**写作顺序**：不是从 Ch1 写到 Ch5，而是按依赖关系调整：

```
执行顺序：Ch1 → Ch3 → Ch2 → Ch4 → Ch5
原因：Ch3（LLM 基础）是 Ch4（工具调用）的前置，
     Ch2（历史）相对独立可灵活安排
```

## 附录：快速参考卡片

### A. 每章写作 SOP（标准操作流程）

```
1. 阅读该章的"详细设计"（详细设计文档第二部分）
2. 阅读原课程对应章节的源文件
3. 写 本章导读（导读 + 学习目标 + 前置知识）
4. 逐节撰写（问题先行 → 类比 → 三层深度）
5. 写动手实践（最小示例 + 常见坑 + 进阶挑战）
6. 写章间桥接（成果 → 缺陷 → 预告）
7. 写习题（概念×2 + 动手×2 + 开放×1）
8. 更新贯穿案例代码
```

### B. 常见写作陷阱

| 陷阱 | 症状 | 解决 |
|------|------|------|
| "知识的诅咒" | 你觉得显然的事，读者完全不懂 | 找一个非技术朋友试读 |
| "定义堆砌" | 一段话出现 3+ 个新概念 | 每个概念至少 200 字展开 |
| "代码太长" | 正文中代码超过 30 行 | 拆分或移到仓库 |
| "类比缺失" | 引入概念时没有类比 | 检查类比库，缺失就补 |
| "桥接遗漏" | 章结尾没有"还缺什么" | 强制模板包含此项 |
