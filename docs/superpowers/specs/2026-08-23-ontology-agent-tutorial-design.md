# 本体论 + Agent 学习教程方案设计

## 目标

在 `本体论-agent/` 下新增一份 Markdown 学习教程方案，帮助两类读者建立完整认知：

- 本体论初学者：理解本体论、RDF、RDFS、OWL、SPARQL、推理和知识图谱。
- Agent 开发者：理解本体论如何增强上下文管理、记忆、工作流、工具、权限和异常处理。

教程最终目标是让读者能够设计并实现一个“本体论增强的企业知识助手”，而不是只停留在概念介绍或知识图谱查询。

## 核心定位

本体论定位为 Agent 的**语义基础层**，不是 Agent 的某一个孤立模块，也不简单等同于记忆。

```text
用户输入
   |
   v
语义基础层：本体论
   |
   +--> 上下文管理：筛选相关实体、关系和约束
   +--> 记忆/知识图谱：定义知识的概念结构
   +--> 工作流：描述任务、角色、状态和前置条件
   +--> 工具系统：描述工具能力、参数和适用条件
   +--> 权限：描述角色、资源和动作关系
   +--> 异常处理：发现类型错误、冲突和约束违规
```

必须明确区分：

```text
本体论       = 概念、关系、约束和规则如何定义
知识图谱     = 具体实体、事实和关系如何保存
Agent        = 如何利用语义和事实完成任务
```

## 贯穿案例

使用“企业知识助手”作为贯穿案例，避免绑定某个具体行业，同时足以覆盖本体建模和 Agent 工程。

核心概念包括：

```text
产品、模块、功能、问题、解决方案、文档、角色、流程、权限、风险
```

核心业务链路：

```text
用户问题
  -> Agent 识别实体和意图
  -> 本体约束校验
  -> SPARQL / 向量检索 / 业务工具
  -> 汇总事实与证据
  -> Agent 生成回答或执行建议
  -> 高风险操作进入人工审核
```

最终案例至少支持：

- 基于概念和关系的知识问答。
- 多跳关系查询。
- 结构化事实与文档片段联合检索。
- 本体约束下的工具调用和参数校验。
- 证据链和回答解释。
- 高风险操作进入 HITL 审核。

## 教程结构

### 第一阶段：建立概念基础

1. 为什么 Agent 需要本体论。
2. 本体论、知识图谱、RAG、数据库的区别。
3. Agent 架构中的本体论位置：语义基础层与六类 Agent 能力的关系。
4. 类、实例、属性、关系、层级、约束和规则。

### 第二阶段：掌握本体技术

5. RDF、RDFS、OWL 和 SPARQL 基础。
6. 从业务问题抽取本体概念。
7. 设计企业知识助手本体。
8. 创建实例数据和知识图谱。
9. 使用 SPARQL 进行结构化查询。
10. 规则推理、一致性校验和本体演进。

### 第三阶段：接入 Agent

11. 本体论增强上下文管理和记忆。
12. 本体论增强 RAG：实体识别、关系扩展和混合检索。
13. 本体论驱动 Agent 的意图识别和查询规划。
14. 本体论驱动工具选择、参数校验和结果约束。
15. 本体论与工作流：任务、角色、状态、前置条件和分支。
16. 本体论与权限、安全边界和异常处理。

### 第四阶段：完成工程闭环

17. 多轮对话中的实体、关系和状态管理。
18. 使用 LangGraph 编排本体查询、Agent、工具和人工审核。
19. 可解释回答、证据链和失败降级。
20. 完整项目：企业知识助手。
21. 测试、评估、版本演进和生产化。

## 每章写作模板

每一章统一包含：

1. 本章目标。
2. 问题背景。
3. 核心概念。
4. 一张或多张 Mermaid 图。
5. 最小代码或数据示例。
6. 贯穿案例改造。
7. 常见错误和排查方式。
8. 练习任务和自查清单。
9. 本章小结。

## 配图要求

教程采用“图先于文字”的表达方式。图不是装饰，而是用来表达结构、边界、数据流、状态变化和角色关系。

### 数量要求

- 每章至少 1 张核心图。
- 概念基础章节：每章 1-2 张，优先使用概念关系图、分层图和对比图。
- Agent 集成章节：每章 2-3 张，至少包含一张架构图或数据流图。
- LangGraph、工具、权限、HITL 和完整项目章节：每章 3-4 张，覆盖架构、时序、状态机和异常路径。
- 全套教程预计不少于 30 张有效图。

### 图的类型

根据内容选择合适的图，不用一种图表达所有问题：

| 内容 | 推荐图形 | 主要表达什么 |
|---|---|---|
| 本体论概念 | 类层级图、关系图、概念对比图 | 类、实例、属性、继承和语义边界 |
| RDF/OWL/SPARQL | 三元组图、数据流图、查询流程图 | 数据如何表达、查询和返回 |
| 本体建模 | 领域模型图、建模流程图、约束图 | 从业务问题到类和关系的转换 |
| 知识图谱 | 实体关系图、多跳查询图 | 事实、路径和证据来源 |
| RAG | 混合检索链路图、召回对比图 | 关键词、向量和结构化检索如何协同 |
| Agent | 分层架构图、能力地图、决策流程图 | 本体论如何连接上下文、记忆、工具和工作流 |
| 工具调用 | 工具选择时序图、参数校验流程图 | 语义匹配、参数约束和执行结果 |
| 工作流 | 状态机、流程图、分支图 | 节点、状态、前置条件和恢复路径 |
| 权限与异常 | 权限关系图、异常决策树、降级流程图 | 谁能做什么、何时拒绝、如何恢复 |
| HITL | 角色时序图、中断恢复图、状态图 | 普通用户、审核人、Agent 和后端的交互 |
| 完整项目 | 总体架构图、部署图、端到端时序图 | 从请求到结果的完整闭环 |

### 图的写作规范

- 每张图必须有标题，并在图后用 2-5 句话解释阅读顺序和关键结论。
- 图中节点名称使用领域术语，避免只写 `Node A`、`Service B` 这类无意义名称。
- 一张图只表达一个主要问题；复杂架构拆成总览图和局部图。
- 优先使用 Mermaid `flowchart`、`sequenceDiagram`、`stateDiagram-v2`、`classDiagram` 和 `erDiagram`。
- 对比图使用左右或上下对称结构，明确标注“相同点”和“差异点”。
- 时序图必须区分普通用户、审核人、Agent、业务 API、工具和存储等角色。
- 状态图必须标明进入条件、成功路径、异常路径和恢复路径。
- 关键图中应明确标注数据格式、ID 边界或约束来源，例如 `user_id`、`task_id`、`thread_id`、`turn_id`。

### 对比度规范

- 所有图使用高对比度配色，节点文字与背景必须清晰可读。
- 默认使用深色文字、浅色背景和少量高饱和强调色。
- 不使用浅灰文字、浅黄背景、低对比度渐变或仅靠颜色区分语义。
- 关键状态同时使用文字标识，例如 `running`、`blocked`、`approved`、`failed`，不能只用颜色表达。
- 同一类角色、数据或状态在全套教程中保持一致的颜色和图例。

### 重点章节配图清单

至少为以下主题安排专门图组：

1. 本体论与 Agent 六类能力的总体关系图。
2. 本体论、知识图谱、RAG、数据库和记忆的对比图。
3. 企业知识助手本体的类层级和关系图。
4. RDF 三元组到知识图谱的转换图。
5. SPARQL 查询执行流程图。
6. 规则推理前后的事实变化图。
7. 本体论增强 RAG 的混合检索链路图。
8. Agent 意图识别到查询规划的决策图。
9. 工具能力匹配和参数校验时序图。
10. 本体论驱动工作流状态机。
11. 权限判断和拒绝路径决策树。
12. 异常分类、重试、降级和人工接管流程图。
13. 普通用户与审核人参与的 HITL 完整时序图。
14. `task_id`、`thread_id`、`turn_id` 和事件记录关系图。
15. 企业知识助手端到端架构图和部署图。

## 技术路线

教程以 Python 为主，技术选型保持可替换：

- RDF/OWL/SPARQL：用于表达和查询语义知识。
- Python 本体和图谱库：用于最小可运行示例。
- 向量检索：用于非结构化文档补充。
- LangGraph：用于状态管理、工作流、流式输出和 HITL。
- 数据库或图数据库：在生产化章节中讨论持久化方案，不把教程绑定到单一厂商。

示例代码要优先展示数据流和边界，不在早期章节引入复杂部署、分布式任务队列或多模型路由。

## 交付文件

目标文件：

```text
本体论-agent/本体论+Agent学习教程方案.md
```

该文件是教程路线和内容设计，不要求本轮同时实现完整项目代码。方案中需要列出后续建议的目录结构、示例代码目录、数据文件目录和最终项目验收标准。

## 验收标准

- 能明确解释本体论在 Agent 架构中的位置。
- 能区分本体论、知识图谱、记忆、RAG 和 Agent。
- 能从业务问题抽取概念、关系和约束。
- 能设计并查询企业知识助手的最小本体。
- 能说明本体论如何影响上下文、工具、工作流、权限和异常处理。
- 能完成一个本体论增强 Agent 的端到端学习项目。
- 文档结构适合后续拆分为多篇章节，并包含练习、图和验证标准。
