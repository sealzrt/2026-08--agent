# Agent 记忆：打造能自我改进的 Agent

## 2. 理解 Agent 记忆

Agent 记忆的本质是**让 Agent 能保留和回忆信息的机制**——对话细节、用户偏好、过往动作、学到的模式等。

没有记忆的 AI 应用是无状态的：每次交互都从零开始，Agent "忘记"之前的上下文和偏好，用户体验重复而令人沮丧。

### 记忆为什么重要

Agent 的智能与它回忆和利用过往信息的能力深度绑定。记忆让 Agent 能够：

- **反思（Reflective）**：从过去的行动和结果中学习。
- **交互（Interactive）**：在持续对话中保持上下文。
- **主动与响应（Proactive & Reactive）**：基于历史数据预判需求或恰当回应。
- **自主（Autonomous）**：借助存储的知识更独立地运作。

实现记忆的目标：让 Agent 更可靠、更有能力。

## 3. 记忆的类型

| 类型 | 作用 | 示例 |
|------|------|------|
| **工作记忆（Working）** | 单个任务/思考过程中的"草稿纸"，保存计算下一步所需的即时信息 | 旅行 Agent 记住当前请求"我要订去巴黎的行程" |
| **短期记忆（Short-Term）** | 单次会话内保留信息，即当前对话的上下文 | 用户问完"去巴黎的机票多少钱"再问"那里的住宿呢"，Agent 知道"那里"指巴黎 |
| **长期记忆（Long-Term）** | 跨会话持久保留：用户偏好、历史交互、常识——个性化的关键 | 记住"Ben 喜欢滑雪和户外活动、喜欢有山景的咖啡、因旧伤要避开高级雪道"，影响未来的行程推荐 |
| **人设记忆（Persona）** | 帮 Agent 保持一致的"个性"/角色 | "滑雪规划专家"人设让回复始终符合专家的语气和知识 |
| **情景/工作流记忆（Episodic）** | 记录复杂任务中的步骤序列，包括成功和失败 | 上次订某航班因无票失败，这次直接尝试替代航班或更明智地告知用户 |
| **实体记忆（Entity）** | 从对话中抽取并记住实体（人/地点/事物）和事件，构建结构化理解 | 从聊过的行程中抽取"巴黎""埃菲尔铁塔""Le Chat Noir 餐厅"，未来主动提出再订这家餐厅 |
| **结构化 RAG（Structured RAG）** | 从对话/邮件/图片等来源抽取密集的结构化信息，提升精度、召回和速度。与只靠语义相似度的经典 RAG 不同，它利用信息的内在结构 | 从邮件解析航班细节（目的地/日期/时间/航司）结构化存储，支持精确查询"我周二订的去巴黎的是哪趟航班？" |

**短期记忆在 MAF 中的对应**：在 Microsoft Agent Framework Python SDK 中，短期记忆对应 `AgentSession`（由 `agent.create_session()` 创建）。会话是框架内置的短期记忆：同一 session 复用期间上下文可用，但 session 结束或应用重启后不保留。需要跨会话存续的事实和偏好要用长期记忆——通常通过数据库、向量索引或其他持久化存储实现。

## 4. 实现与存储记忆

记忆管理是一个系统性过程：**生成、存储、检索、整合、更新，甚至"遗忘"（删除）**。其中检索尤为关键。

### 4.1 Mem0：持久记忆层

Mem0 作为持久记忆层，让 Agent 能回忆相关交互、存储用户偏好和事实上下文、从成功和失败中学习——把无状态 Agent 变成有状态 Agent。

工作机制是**两阶段记忆流水线**：

1. **抽取（Extraction）**：加入 Agent 线程的消息发送给 Mem0 服务，由 LLM 总结对话历史、抽取新记忆。
2. **更新（Update）**：LLM 驱动的更新阶段决定对这些记忆做添加、修改还是删除，最终存入混合数据存储（向量库、图数据库、KV 库均可）。

Mem0 支持多种记忆类型，还可引入图记忆来管理实体间的关系。

### 4.2 Cognee：知识图谱语义记忆

Cognee 是开源的 Agent 语义记忆方案，把结构化/非结构化数据转换成**由向量支撑的可查询知识图谱**。

- **双存储架构**：向量相似搜索 + 图关系，让 Agent 不仅知道"哪些信息相似"，还知道"概念之间如何关联"。
- **混合检索**：融合向量相似度、图结构和 LLM 推理——从原始分块查找到图感知的问答。
- **活的记忆**：记忆持续演化生长，同时保持为一张可查询的连通图，同时支持短期会话上下文和长期持久记忆。

配套 notebook 演示了统一记忆层的构建：摄入多样数据源、可视化知识图谱、按 Agent 需求选择不同检索策略。

### 4.3 Azure AI Search：RAG 存储后端

除了 Mem0 这类专门工具，也可以用 Azure AI Search 这样健壮的搜索服务作为记忆的存取后端，尤其适合结构化 RAG：

- 用自己的数据"锚定"（ground）Agent 的回答，确保答案更相关准确。
- 可存储用户专属的旅行记忆、产品目录或任何领域知识。
- 支持结构化 RAG——擅长从对话历史、邮件甚至图片等大数据集中抽取和检索密集的结构化信息，相比传统的文本分块+向量化，提供"超人级的精度与召回"。

## 5. 让 Agent 自我改进

一种常见的自我改进模式是引入**"知识 Agent"（knowledge agent）**：一个独立的 Agent 旁观用户与主 Agent 的对话，职责是：

1. **识别有价值的信息**：判断对话中是否有值得保存的通用知识或用户偏好。
2. **抽取与总结**：从对话中提炼核心的经验或偏好。
3. **存入知识库**：把抽取的信息持久化（通常存向量库）供日后检索。
4. **增强未来查询**：用户发起新查询时，知识 Agent 检索相关的已存信息并附加到用户 prompt 上，为主 Agent 提供关键上下文（类似 RAG）。

### 记忆的优化技巧

- **延迟管理**：为避免拖慢用户交互，可以先用便宜快速的小模型判断信息是否值得存储/检索，必要时才启动更复杂的抽取/检索流程。
- **知识库维护**：知识库不断增长时，把低频使用的信息移入"冷存储"以控制成本。

## 6. 小结

| 要点 | 内容 |
|------|------|
| 记忆的价值 | 让 Agent 具备反思、交互、主动响应、自主四种能力 |
| 类型体系 | 工作/短期/长期 + 人设/情景/实体/结构化 RAG |
| 实现方案 | Mem0（两阶段流水线）、Cognee（知识图谱）、Azure AI Search（结构化 RAG 后端） |
| 自我改进 | "知识 Agent"旁观-抽取-存储-增强的闭环 |
| 优化 | 小模型预判 + 冷存储分层 |
