> 📖 **库**（library）： loosely 指可复用的代码集合（可以是模块、包、或两者都有）。

## 11.1 导入模块的四种写法

```python
# 1. 导入整个模块
import math
math.sqrt(16)        # 4.0

# 2. 导入并取别名
import numpy as np
np.array([1, 2, 3])

# 3. 从模块里导入特定对象
from math import sqrt, pi
sqrt(16)             # 4.0

# 4. 导入模块里所有公开对象（慎用）
from math import *
```

| 写法 | 优点 | 缺点 |
| --- | --- | --- |
| `import X` | 命名空间清晰 | 每次用都要写 `X.foo` |
| `import X as Y` | 短名（`np`） | 要知道约定别名 |
| `from X import foo` | 直接用 `foo` | 多个导入可能冲突 |
| `from X import *` | 最省字 | 严重污染命名空间，不推荐 |

💡 **经验**：标准库常用 `import X`，第三方库按约定（`np`、`pd`），函数级别导入只在该函数很常用时。

## 11.3 写自己的模块

`myutils.py`：

```python
# myutils.py
"""我的工具模块"""

PI = 3.14159

def greet(name):
    return f"你好，{name}"

class Person:
    def __init__(self, name):
        self.name = name
```

在另一个文件里：

```python
import myutils
print(myutils.greet("小明"))
print(myutils.PI)
p = myutils.Person("小红")
```

### 11.3.1 `if __name__ == "__main__"`

```python
# myutils.py
def main():
    print("测试 greet:", greet("测试"))

if __name__ == "__main__":
    # 只有"直接运行 myutils.py"时才会执行
    # 被 import 时不执行
    main()
```

📖 **`__name__`**：每个模块都有这个属性。被 import 时是模块名（如 `"myutils"`），直接运行时是 `"__main__"`。这个判断让文件"既能当模块，又能当脚本"。

### 11.3.2 `__main__.py`

把包变成"可运行的"：

```
mypackage/
    __init__.py
    __main__.py   ← python -m mypackage 时会执行这个
    core.py
```

```python
# mypackage/__main__.py
from .core import run
run()
```

```powershell
$ python -m mypackage     # 执行 __main__.py
```

## 11.4 写自己的包

目录结构：

```
my_package/
    __init__.py          ← 必需（可为空）
    utils.py
    models/
        __init__.py
        user.py
```

使用：

```python
from my_package import utils
from my_package.models.user import User
```

### 11.4.1 `__init__.py` 的作用

- 标记"这个目录是包"（Python 3.3+ 已不强制，但仍推荐）
- 可以在里面定义包级别的导出：

```python
# my_package/__init__.py
from .utils import greet
from .models.user import User

__all__ = ["greet", "User"]   # 显式声明 from x import * 时导出哪些
```

### 11.4.2 相对导入

```python
# 在 my_package/utils.py 里
from .models.user import User     # 同包内的相对导入
from ..common import config       # 父包
```

⚠️ **相对导入只能在包内使用**，直接运行的脚本（`__name__ == "__main__"`）不能用相对导入。

## 11.5 `pip` 包管理器

### 11.5.1 基础命令

```powershell
# 安装
$ pip install requests
$ pip install requests==2.31.0         # 指定版本
$ pip install "requests>=2.30,<3"      # 版本范围

# 卸载
$ pip uninstall requests

# 查看已装
$ pip list
$ pip show requests

# 升级
$ pip install --upgrade requests

# 从 requirements.txt 批量装
$ pip install -r requirements.txt

# 生成 requirements.txt
$ pip freeze > requirements.txt
```

### 11.5.2 PyPI 镜像

国内直连 PyPI 慢，配国内镜像：

```powershell
$ pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple/
```

或永久配置（清华镜像）：

```powershell
$ pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple/
```

## 11.6 虚拟环境：项目隔离

> 📖 **虚拟环境**（venv）：每个项目有自己独立的 Python 和依赖包——A 项目用 pandas 2.0、B 项目用 pandas 1.5，互不干扰。

### 11.6.1 创建和激活

```powershell
# 创建（在项目根目录下）
$ python -m venv .venv

# 激活（Windows）
$ .venv\Scripts\activate
(.venv) $              # 命令行前面多了 (.venv)，表示在虚拟环境里

# 停用
(.venv) $ deactivate
```

```bash
# Linux / macOS
$ python3 -m venv .venv
$ source .venv/bin/activate
```

### 11.6.2 标准工作流

```powershell
# 1. 进入项目目录
$ cd myproject

# 2. 创建虚拟环境
$ python -m venv .venv

# 3. 激活
$ .venv\Scripts\activate

# 4. 安装依赖
(.venv) $ pip install requests pandas openpyxl

# 5. 锁定依赖
(.venv) $ pip freeze > requirements.txt

# 6. 把 .venv 加入 .gitignore（不要提交虚拟环境）
```

VS Code 会自动识别项目里的 `.venv`，把 Python 解释器切过去。

### 11.6.3 其他虚拟环境工具

| 工具 | 特点 |
| --- | --- |
| `venv` | 内置，够用 |
| `virtualenv` | 第三方，比 venv 快一些 |
| `conda` | 数据科学标配，管理 Python 版本+包 |
| `poetry` | 现代项目/依赖管理（类 npm/cargo） |
| `uv` | 超快的新一代工具（Rust 写的） |

💡 **经验**：新手用 `venv` 足够；做数据科学用 `conda`；想"一步到位"学 `poetry`。

## ⚠️ 本章踩坑提醒

1. **`pip install` 装到全局**：一定要先激活虚拟环境
2. **`from X import *`**：污染命名空间，调试时找不到符号来源
3. **相对导入用在直接运行的脚本**：会报 `ImportError`
4. **循环导入**：`a.py import b`，`b.py import a`——拆模块或延迟导入
5. **`.venv` 提交到 git**：巨大、平台相关，加入 `.gitignore`
