## 各目录职责

### app/state.py

只定义状态结构和公共类型：

```python
from typing import TypedDict


class ResearchState(TypedDict):
    topic: str
    documents: list[str]
    summary: str
    quality_score: int
    final_report: str
```

### app/nodes/

每个文件放一类节点。节点读取 `State`，调用业务函数或工具，返回状态更新。

### app/tools/

工具只负责外部能力，例如搜索、数据库查询、HTTP 请求。工具不直接依赖 LangGraph。

### app/prompts/

Prompt 独立存放，便于修改和评审。

### app/graph.py

集中创建图：

```python
from langgraph.graph import END, START, StateGraph

from app.state import ResearchState
from app.nodes.search import search_documents
from app.nodes.summarize import summarize_documents


def build_graph():
    builder = StateGraph(ResearchState)
    builder.add_node("search_documents", search_documents)
    builder.add_node("summarize_documents", summarize_documents)
    builder.add_edge(START, "search_documents")
    builder.add_edge("search_documents", "summarize_documents")
    builder.add_edge("summarize_documents", END)
    return builder.compile()
```

### app/api/

只放 API 层，不把图定义和业务逻辑写在接口函数里。

## 贯穿项目改造

本章的目标不是新增复杂功能，而是把已有能力放到正确位置：

- 状态定义集中。
- 节点按职责拆分。
- 工具可替换。
- Prompt 可独立维护。
- API 只做输入输出转换。
- 测试覆盖业务函数、节点和图。

## 代码运行方式

从项目根目录运行：

```powershell
python -m app.graph
```

或运行 API：

```powershell
uvicorn app.api.main:app --reload
```

运行测试：

```powershell
pytest
```

## 常见错误

- `graph.py` 变成巨型文件，塞满所有节点逻辑。
- 工具函数直接读取和修改 `State`。
- Prompt 散落在多个 Python 文件中。
- API 层直接拼 Prompt 或调用模型。
- `.env` 提交到仓库，泄露密钥。
