# 15. 部署与生产化注意事项

## 本章目标

- 理解 LangGraph 项目常见运行方式。
- 知道上线前需要补齐哪些工程能力。
- 设计长任务执行和状态持久化方案。
- 建立生产化检查清单。

## 为什么需要这一章

教程项目能跑，不代表可以直接上线。生产环境需要考虑并发、超时、成本、权限、日志、持久化、失败恢复和数据安全。

LangGraph 负责图工作流，但不替代完整的后端架构。

## 运行方式

### 本地脚本

适合学习、调试和批处理：

```powershell
python examples/run_graph.py
```

### Web API

适合由前端或其他服务触发：

```powershell
uvicorn app.api.main:app --host 0.0.0.0 --port 8000
```

### 后台任务

适合长时间运行任务：

```text
API 创建任务 -> 队列投递 -> Worker 执行图 -> 状态写入存储 -> 前端订阅事件
```

入门教程不需要实现完整队列，但要说明真实项目中不能让长任务长期占用一个 HTTP 请求。

## 关键生产化问题

### 配置和密钥

- API Key 放环境变量或密钥管理系统。
- 仓库只提交 `.env.example`。
- 不在日志中输出完整 Prompt、用户隐私或密钥。

### 持久化

- 教程可用内存型 checkpointer。
- 生产应使用 SQLite、Postgres 或其他持久化存储。
- 业务数据应进入业务数据库，不要长期堆在 `State` 中。

### 超时和重试

- 工具调用要设置超时。
- 网络失败可以技术重试。
- 总结质量不达标是业务循环，不要和技术重试混在一起。
- 图调用要设置 `recursion_limit`。

### 成本控制

- 限制最大循环次数。
- 限制单次输入上下文长度。
- 对检索资料做裁剪和去重。
- 对失败任务记录原因，避免重复烧模型调用。

### 权限和审计

- 人工审批要记录审批人、审批时间、审批意见。
- 高风险任务需要人工确认。
- 用户只能查看自己的任务状态和报告。

### 观测和告警

- 记录每个节点耗时。
- 记录工具调用成功率和失败原因。
- 记录模型调用 token、耗时和费用估算。
- 对长时间卡住、频繁失败、递归超限建立告警。

## 最小部署接口

```text
POST /tasks
GET /tasks/{task_id}
GET /tasks/{task_id}/events
POST /tasks/{task_id}/feedback
GET /tasks/{task_id}/report
```

任务状态建议：

```text
created
running
interrupted
failed
completed
cancelled
```

## 生产化检查清单

- 是否有 `.env.example`，且没有提交真实 `.env`。
- 是否有明确的模型配置。
- 是否限制最大循环次数。
- 是否设置 `recursion_limit`。
- 是否处理工具超时和失败。
- 是否区分 checkpointer 和业务数据库。
- 是否能按 `thread_id` 恢复任务。
- 是否能处理人工反馈。
- 是否有节点级日志。
- 是否有基础单元测试和图级集成测试。
- 是否有任务状态接口。
- 是否有成本和并发限制。
- 是否有错误告警。

## 贯穿项目最终形态

最终的“资料检索与总结 Agent”应具备：

```text
用户创建任务
  -> 分析主题
  -> 制定检索计划
  -> 检索资料
  -> 总结资料
  -> 评估质量
  -> 必要时补充检索
  -> 生成报告草稿
  -> 人工确认
  -> 输出最终报告
```

它应该支持：

- 模拟模式：无真实模型和外部检索，适合测试。
- 真实模式：调用真实模型和工具，适合验收。
- 会话恢复：通过 `thread_id` 找回任务状态。
- 流式输出：前端能看到节点进度。
- 人工介入：用户能审批或补充要求。

## 常见错误

- 把教程里的内存持久化直接用于生产。
- 让长任务阻塞 HTTP 请求。
- 没有成本限制，循环和模型调用失控。
- 没有人工审批审计。
- 没有记录中间状态，出错后无法复盘。
