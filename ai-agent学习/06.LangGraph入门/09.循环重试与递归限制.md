# 09. 循环、重试与递归限制

## 本章目标

- 理解 Agent 为什么需要循环。
- 使用状态字段控制业务循环次数。
- 使用 `recursion_limit` 控制运行时最大步数。
- 区分失败重试和业务重试。

## 为什么需要这一章

资料不足时，Agent 需要继续检索；总结质量不达标时，Agent 需要补充资料后重新总结。这就是业务循环。

但循环必须可终止。否则一次图调用可能无限执行。LangGraph 提供运行时递归限制，业务代码也应设置自己的最大次数。

## 核心概念

### 业务循环

业务循环由状态字段控制，例如：

```python
iteration_count: int
max_iterations: int
quality_score: int
```

### recursion_limit

`recursion_limit` 是 LangGraph 的运行时保护。它在调用图时通过 config 传入：

```python
result = graph.invoke(
    initial_state,
    {"recursion_limit": 100},
)
```

业务循环限制解决“什么时候应该停”，`recursion_limit` 解决“代码写错时不要无限跑”。

## 最小代码示例

```python
from typing import Literal, TypedDict

from langgraph.graph import END, START, StateGraph


class ResearchState(TypedDict):
    topic: str
    documents: list[str]
    summary: str
    quality_score: int
    iteration_count: int
    max_iterations: int


def search_documents(state: ResearchState) -> dict[str, object]:
    next_count = state["iteration_count"] + 1
    return {
        "documents": state["documents"] + [f"第 {next_count} 轮检索资料"],
        "iteration_count": next_count,
    }


def summarize_documents(state: ResearchState) -> dict[str, str]:
    return {"summary": f"基于 {len(state['documents'])} 份资料生成总结"}


def evaluate_summary(state: ResearchState) -> dict[str, int]:
    score = min(50 + len(state["documents"]) * 20, 95)
    return {"quality_score": score}


def route_after_evaluation(state: ResearchState) -> Literal["retry", "finish"]:
    if state["quality_score"] >= 80:
        return "finish"
    if state["iteration_count"] >= state["max_iterations"]:
        return "finish"
    return "retry"


builder = StateGraph(ResearchState)
builder.add_node("search_documents", search_documents)
builder.add_node("summarize_documents", summarize_documents)
builder.add_node("evaluate_summary", evaluate_summary)

builder.add_edge(START, "search_documents")
builder.add_edge("search_documents", "summarize_documents")
builder.add_edge("summarize_documents", "evaluate_summary")
builder.add_conditional_edges(
    "evaluate_summary",
    route_after_evaluation,
    {"retry": "search_documents", "finish": END},
)

graph = builder.compile()


if __name__ == "__main__":
    result = graph.invoke(
        {
            "topic": "LangGraph",
            "documents": [],
            "summary": "",
            "quality_score": 0,
            "iteration_count": 0,
            "max_iterations": 3,
        },
        {"recursion_limit": 20},
    )
    print(result)
```

## 贯穿项目改造

流程变成：

```text
search_documents
  -> summarize_documents
  -> evaluate_summary
  -> 质量达标？结束
  -> 质量不达标且未超次数？回到 search_documents
```

## 常见错误

- 只设置 `recursion_limit`，没有业务结束条件。这样只是防崩，不是业务正确。
- 忘记更新 `iteration_count`，导致路由条件永远不变。
- 把工具失败重试和业务补充检索混在一起。工具失败重试通常是技术容错，业务重试是流程决策。
