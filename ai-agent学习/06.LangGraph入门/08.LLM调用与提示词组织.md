# 08. LLM 调用与提示词组织

## 本章目标

- 理解在节点中调用 LLM 的位置。
- 用 Prompt 明确模型输入和输出。
- 使用结构化输出降低解析风险。
- 提供模拟模式和真实模式两种运行方式。

## 为什么需要这一章

LangGraph 负责编排流程，LLM 负责处理不确定的语言任务。两者职责不同：不要把 LangGraph 当模型，也不要把模型当流程引擎。

本章先用模拟 LLM 保证可复现，再说明如何替换成真实模型。

## 核心概念

### Prompt 是接口契约

服务端接口会定义请求和响应。LLM 节点也应该定义输入和输出契约。

例如评估总结质量时，不要只让模型“评价一下”，而要要求输出：

```json
{
  "quality_score": 80,
  "missing_points": ["缺少部署说明"]
}
```

### 模拟模式

模拟模式不调用真实模型，用固定逻辑返回结构化数据。它适合写教程、测试和调试流程。

### 真实模式

真实模式调用模型 API。它适合验证实际效果，但会受到网络、成本和模型稳定性的影响。

## 最小代码示例

```python
from typing import TypedDict


class SearchResult(TypedDict):
    title: str
    content: str


class Evaluation(TypedDict):
    quality_score: int
    missing_points: list[str]


class ResearchState(TypedDict):
    topic: str
    documents: list[SearchResult]
    summary: str
    quality_score: int
    missing_points: list[str]


def mock_summarize(topic: str, documents: list[SearchResult]) -> str:
    titles = "、".join(doc["title"] for doc in documents)
    return f"主题《{topic}》的总结。参考资料：{titles}"


def mock_evaluate(summary: str) -> Evaluation:
    if len(summary) > 40:
        return {"quality_score": 85, "missing_points": []}
    return {"quality_score": 60, "missing_points": ["总结太短"]}


def summarize_documents(state: ResearchState) -> dict[str, str]:
    return {
        "summary": mock_summarize(state["topic"], state["documents"])
    }


def evaluate_summary(state: ResearchState) -> dict[str, object]:
    result = mock_evaluate(state["summary"])
    return {
        "quality_score": result["quality_score"],
        "missing_points": result["missing_points"],
    }
```

## 真实模型替换思路

真实模式可以把 `mock_summarize()` 替换成模型调用函数：

```python
def summarize_with_llm(topic: str, documents: list[SearchResult]) -> str:
    prompt = f"""
请基于资料总结主题：{topic}

资料：
{documents}

要求：
1. 用中文输出
2. 结构清晰
3. 不要编造资料中没有的信息
"""
    # 在这里调用你的模型 SDK
    return call_llm(prompt)
```

教程正文应把模型调用封装在独立函数里，不要让节点直接拼大量 Prompt。

## 常见错误

- Prompt 太散，输出结构不可控。
- 节点直接依赖具体模型 SDK，后续难以替换。
- 测试依赖真实模型，导致结果不稳定。
- 没有兜底处理，模型返回非 JSON 时流程直接崩溃。
