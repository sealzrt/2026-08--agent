# 12. 流式输出与前端集成

## 本章目标

- 理解为什么 Agent 需要流式输出。
- 区分 `stream()` 和 `stream_events()`。
- 设计前端可消费的任务状态。
- 用 FastAPI 包装最小接口。

## 为什么需要这一章

Agent 工作流可能运行几十秒甚至更久。前端不能只显示一个转圈加载。用户需要知道当前执行到哪个节点、是否正在调用模型、是否等待人工确认、最终结果是什么。

LangGraph 提供流式输出能力，可以把节点更新和模型消息逐步推给调用方。

## 核心概念

### graph.stream

`graph.stream(..., stream_mode=...)` 适合获取图执行过程中的状态输出。

常见模式：

- `updates`：输出每个节点返回的局部状态更新。
- `values`：输出每一步之后的完整状态。
- `messages`：输出模型 token 和消息元数据。
- `custom`：输出自定义数据。
- `debug`：输出调试信息。

### graph.stream_events

`graph.stream_events(..., version="v3")` 更适合前端或可观测系统消费类型化事件。它关注事件，而不是只关注状态。

入门建议：

- 后端内部调试优先使用 `stream(..., stream_mode="updates")`。
- 前端事件流优先设计为对接 `stream_events(..., version="v3")`。

## 最小代码示例

```python
config = {"configurable": {"thread_id": "stream-001"}}

for chunk in graph.stream(
    {
        "topic": "LangGraph 流式输出",
        "documents": [],
        "summary": "",
    },
    config,
    stream_mode="updates",
):
    print(chunk)
```

前端事件可以统一整理为：

```json
{
  "task_id": "stream-001",
  "node": "summarize_documents",
  "status": "running",
  "event_type": "node_update",
  "payload": {}
}
```

## 贯穿项目改造

建议前端展示这些节点状态：

```text
analyze_topic: waiting | running | done | error
search_documents: waiting | running | done | error
summarize_documents: waiting | running | done | error
evaluate_summary: waiting | running | done | error
human_review: waiting | interrupted | done
generate_report: waiting | running | done | error
```

最小 API：

```text
POST /tasks
GET /tasks/{task_id}
POST /tasks/{task_id}/feedback
GET /tasks/{task_id}/events
```

## FastAPI 接口草图

```python
from fastapi import FastAPI
from pydantic import BaseModel


app = FastAPI()


class CreateTaskRequest(BaseModel):
    topic: str


class FeedbackRequest(BaseModel):
    approved: bool
    comment: str = ""


@app.post("/tasks")
def create_task(request: CreateTaskRequest) -> dict[str, str]:
    task_id = "research-001"
    return {"task_id": task_id}


@app.post("/tasks/{task_id}/feedback")
def submit_feedback(task_id: str, request: FeedbackRequest) -> dict[str, str]:
    return {"task_id": task_id, "status": "submitted"}
```

这一章只设计接口，不必一次性实现复杂前端。

## 常见错误

- 只返回最终结果，用户无法知道长任务进度。
- 把节点内部日志直接当作前端事件，结构不稳定。
- 没有区分任务状态和最终业务结果。
- 前端不知道 interrupt 状态，导致用户无法提交反馈。

## 练习任务

必做：

- 为每个节点设计 `waiting/running/done/error` 状态。

扩展：

- 使用 SSE 返回事件流，让前端实时展示节点进度。
