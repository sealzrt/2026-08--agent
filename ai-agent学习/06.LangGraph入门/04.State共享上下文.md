# 04. State：让工作流拥有共享上下文

## 本章目标

- 理解 `State` 是图执行过程中的共享上下文。
- 使用 `TypedDict` 定义业务状态。
- 理解节点如何读取状态、返回状态更新。
- 初步理解 reducer 的作用。

## 为什么需要这一章

单节点图不太需要复杂状态。真实 Agent 会有多个步骤：分析主题、检索资料、总结、评分、生成报告。这些步骤必须共享数据。LangGraph 的 `State` 就是这份共享上下文。

## 核心概念

### State 是上下文，不是数据库

`State` 保存的是一次图执行过程中需要流转的数据。它可以被持久化，但不要把它当成完整业务数据库。

### 节点返回局部更新

节点通常不需要返回整个状态，只返回自己修改的字段：

```python
def node(state: ResearchState) -> dict[str, str]:
    return {"summary": "新的总结"}
```

LangGraph 会把这个更新合并回状态。

### 默认覆盖

如果节点返回同名字段，默认会覆盖旧值。比如 `summary` 会被新值替换。

### reducer

如果多个节点都要追加列表，就需要 reducer。入门阶段可以先不用复杂 reducer，只知道它用于控制合并策略。

## 最小代码示例

创建文件 `04_state_graph.py`：

```python
from typing import TypedDict

from langgraph.graph import END, START, StateGraph


class ResearchState(TypedDict):
    topic: str
    questions: list[str]
    documents: list[str]
    summary: str
    quality_score: int


def analyze_topic(state: ResearchState) -> dict[str, list[str]]:
    return {
        "questions": [
            f"{state['topic']} 是什么？",
            f"{state['topic']} 适合解决什么问题？",
        ]
    }


def search_documents(state: ResearchState) -> dict[str, list[str]]:
    documents = [f"资料：{question}" for question in state["questions"]]
    return {"documents": documents}


def summarize_documents(state: ResearchState) -> dict[str, str]:
    return {
        "summary": f"基于 {len(state['documents'])} 份资料，总结主题：{state['topic']}"
    }


builder = StateGraph(ResearchState)
builder.add_node("analyze_topic", analyze_topic)
builder.add_node("search_documents", search_documents)
builder.add_node("summarize_documents", summarize_documents)

builder.add_edge(START, "analyze_topic")
builder.add_edge("analyze_topic", "search_documents")
builder.add_edge("search_documents", "summarize_documents")
builder.add_edge("summarize_documents", END)

graph = builder.compile()


if __name__ == "__main__":
    result = graph.invoke({
        "topic": "LangGraph",
        "questions": [],
        "documents": [],
        "summary": "",
        "quality_score": 0,
    })
    print(result)
```

## 贯穿项目改造

项目状态从两个字段扩展到五个字段：

```python
class ResearchState(TypedDict):
    topic: str
    questions: list[str]
    documents: list[str]
    summary: str
    quality_score: int
```

每个节点只关心自己需要的输入和输出：

- `analyze_topic` 读取 `topic`，写入 `questions`。
- `search_documents` 读取 `questions`，写入 `documents`。
- `summarize_documents` 读取 `documents`，写入 `summary`。

## 代码运行方式

```powershell
python 04_state_graph.py
```

## 常见错误

- 初始状态缺字段：`TypedDict` 描述了字段，但运行时仍需要你传入必要字段。
- 把临时变量都塞进状态：只有后续节点需要的数据才放进 `State`。
- 节点返回值类型不稳定：同一个字段不要有时返回字符串，有时返回列表。
