# 13. 调试、观测与测试

## 本章目标

- 为节点增加基础日志。
- 区分节点单元测试和图级集成测试。
- 理解如何测试不稳定的 LLM 输出。
- 了解 LangSmith 的调试和 trace 价值。

## 为什么需要这一章

Agent 出问题时，不能只看最终回答。你需要知道哪个节点输入了什么、输出了什么、耗时多久、是否调用了工具、模型返回是否符合预期。

可观测性不是上线后才补的能力，教程项目也应该尽早建立基本习惯。

## 核心概念

### 节点日志

最小日志字段：

- `thread_id`
- `node_name`
- `input_summary`
- `output_summary`
- `duration_ms`
- `error`

### 节点单元测试

单元测试只测单个函数：

```python
def test_evaluate_summary_passes() -> None:
    state = {"summary": "这是一段足够长的总结，包含背景、用途和风险。"}
    result = evaluate_summary(state)
    assert result["quality_score"] >= 80
```

### 图级集成测试

集成测试运行完整图，验证最终状态：

```python
def test_graph_generates_report() -> None:
    result = graph.invoke(initial_state, {"recursion_limit": 20})
    assert result["summary"]
    assert result["quality_score"] > 0
```

## 最小代码示例

```python
import logging
import time
from collections.abc import Callable
from typing import Any


logger = logging.getLogger(__name__)


def log_node(name: str, fn: Callable[[dict[str, Any]], dict[str, Any]]):
    def wrapper(state: dict[str, Any]) -> dict[str, Any]:
        started = time.perf_counter()
        try:
            result = fn(state)
            duration_ms = int((time.perf_counter() - started) * 1000)
            logger.info(
                "node=%s duration_ms=%s output_keys=%s",
                name,
                duration_ms,
                list(result.keys()),
            )
            return result
        except Exception:
            logger.exception("node=%s failed", name)
            raise

    return wrapper
```

## 贯穿项目改造

建议测试顺序：

1. 先测普通业务函数。
2. 再测节点函数。
3. 最后测完整图。

对 LLM 输出：

- 测结构，不强测具体文案。
- 模拟模式用于稳定测试。
- 真实模式用于人工验收或少量集成验证。

## 代码运行方式

安装测试工具：

```powershell
pip install pytest

```

```powershell
$env:LANGSMITH_TRACING="true"
$env:LANGSMITH_API_KEY="你的 LangSmith Key"
```

## 常见错误

- 只测试最终文本，导致测试脆弱。
- 节点没有日志，排查只能靠猜。
- 测试直接依赖真实模型，结果不稳定。
- 错误被吞掉，图看起来结束了但状态不完整。
