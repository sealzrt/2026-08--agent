# 10. 持久化与会话恢复

## 本章目标

- 理解为什么 Agent 需要持久化。
- 掌握 checkpointer 和 `thread_id` 的关系。
- 区分 checkpointer 和 store。
- 使用内存型 checkpointer 演示会话恢复。

## 为什么需要这一章

真实 Agent 可能运行很久，中间还可能等待人工确认。如果没有持久化，服务重启、请求中断或用户稍后回来都会导致状态丢失。

LangGraph 使用 checkpointer 保存线程级执行状态。你可以用 `thread_id` 标识一次会话或一次任务。

## 核心概念

### checkpointer

checkpointer 保存图执行过程中的状态快照。入门阶段可以用内存型 checkpointer。

### thread_id

`thread_id` 用于区分不同会话：

```python
config = {"configurable": {"thread_id": "research-001"}}
```

同一个 `thread_id` 会复用同一条会话状态。不同 `thread_id` 会得到彼此隔离的状态。

### checkpointer 和 store

- `checkpointer`：保存线程级短期执行状态。
- `store`：保存跨线程长期记忆，例如用户偏好、历史知识、长期资料。

不要把二者混成一个概念。

## 最小代码示例

```python
from typing import TypedDict

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import END, START, StateGraph


class ResearchState(TypedDict):
    topic: str
    notes: list[str]


def add_note(state: ResearchState) -> dict[str, list[str]]:
    return {
        "notes": state["notes"] + [f"记录主题：{state['topic']}"]
    }


builder = StateGraph(ResearchState)
builder.add_node("add_note", add_note)
builder.add_edge(START, "add_note")
builder.add_edge("add_note", END)

checkpointer = InMemorySaver()
graph = builder.compile(checkpointer=checkpointer)


if __name__ == "__main__":
    config = {"configurable": {"thread_id": "research-001"}}

    first = graph.invoke(
        {"topic": "LangGraph 持久化", "notes": []},
        config,
    )
    print(first)

    second = graph.invoke(
        {"topic": "LangGraph 持久化", "notes": first["notes"]},
        config,
    )
    print(second)
```

## 贯穿项目改造

贯穿项目需要保存：

- 用户主题。
- 检索计划。
- 已检索资料。
- 总结草稿。
- 质量评分。
- 人工反馈。

第 10 章只演示内存型 checkpointer。生产环境不能依赖它，因为进程重启后状态会丢失。

## 常见错误

- 忘记传 `thread_id`，导致无法按会话恢复。
- 误以为 `InMemorySaver` 可以用于生产。
- 把长期业务数据都塞进 `State`，导致状态越来越大。
- 不区分“恢复执行状态”和“保存业务记录”。
