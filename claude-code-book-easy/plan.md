# Claude Code Book 易学版整理方案

## 1. 整理目标

本目录用于基于 `https://lintsinghua.github.io/#preface` 的《御舆：解码 Agent Harness · Claude Code 架构深度剖析》进行易学化整理。

整理目标不是重新设计一门新课，也不是压缩成摘要，而是在尽量保留原课程大纲、章节顺序和技术内容的基础上，为每章补充导读、概念拆解、学习路径、常见误解和 Harness 迁移总结，让读者更容易理解原课程中的高密度架构内容。

最终产物应帮助读者完成三件事：

1. 按原课程主线理解 Claude Code 的 Agent Harness 架构。
2. 看懂对话循环、工具系统、权限管线、上下文、记忆、Hooks、Subagent、MCP、Skills、Plan 模式等核心机制。
3. 将 Claude Code 的具体设计抽象为通用 Agent Harness 的工程原则。

## 2. 目标读者

适合读者：

- 已经知道什么是 LLM、Agent、工具调用，但对 Harness 工程体系还不完整。
- 读原课程时能看懂部分内容，但容易被大量架构图、术语和机制细节打断。
- 想学习 Claude Code 背后的工程设计，而不只是学习 Claude Code 的使用方法。
- 想把 Claude Code 的设计思想迁移到 Codex、Cursor、OpenHands 或自研 Agent Harness。

不适合读者：

- 完全没有编程基础的读者。
- 只想快速使用 Claude Code 命令的读者。
- 只想看精简摘要、不关心工程细节的读者。

## 3. 与原课程的关系

本整理版遵循以下边界：

- 保留原课程的章节大纲和主要内容顺序。
- 不逐字复制原课程正文。
- 不擅自删减原课程中的关键机制。
- 不把课程改造成完全不同的项目实战课。
- 可以在每章内部增加解释层、导读层、例子和学习检查点。
- 可以把原课程中的复杂段落拆成更小的学习单元。
- 可以补充通用 Harness 视角，但不能让补充内容喧宾夺主。

一句话原则：

```text
原课程负责深度，本整理版负责降低理解成本。
```

## 4. 整理策略

### 4.1 保持原纲

原课程是 15 章 + 4 个附录，本整理版也保持这个结构。目录可以做中英文文件名适配，但章节含义不改变。

每章文件应能明确对应到原课程的一章，避免读者在两个版本之间切换时找不到位置。

### 4.2 增加学习脚手架

每章开头增加“学习脚手架”，帮助读者先建立上下文：

- 本章要解决的问题
- 一句话理解
- 为什么需要这个机制
- 学前需要知道的概念
- 本章阅读顺序建议

### 4.3 降低抽象密度

原课程中很多内容是架构分析式表达，容易一次性引入多个概念。整理时需要拆成：

1. 问题背景：没有这个机制会怎样。
2. 核心直觉：用一句工程化语言说明它在解决什么。
3. 机制拆解：分模块、分流程解释。
4. 设计权衡：为什么这样设计，而不是另一种设计。
5. Harness 迁移：这个机制在通用 Harness 中如何复用。

### 4.4 区分具体实现与通用原则

每章都要区分：

- Claude Code 的具体实现或产品行为。
- 通用 Agent Harness 可以借鉴的设计原则。

例如：

```text
Claude Code 具体实现：Plan Mode、Subagent、Hooks、Skills。
通用 Harness 原则：权限前置、上下文隔离、能力按需加载、生命周期扩展点。
```

### 4.5 保留技术密度

易学化不是浅化。整理版需要保留原课程中的关键技术点，但用更清晰的层次表达。

复杂内容可以拆开讲，不能直接删除。

## 7. 重点难点处理策略

### 7.1 对话循环

难点：

- 容易把 Agent 理解成普通聊天机器人。
- 容易忽略工具结果回填和多轮循环。

处理方式：

- 先用 `messages -> model -> tool call -> tool result -> messages` 的最小循环解释。
- 再解释为什么 Harness 的核心是循环控制和状态更新。

### 7.2 工具系统

难点：

- 容易只关注工具函数本身，忽略工具协议、参数校验、结果结构和错误处理。

处理方式：

- 按工具定义、工具选择、工具执行、结果回填、失败处理拆解。
- 强调工具系统是模型和外部世界之间的边界层。

### 7.3 权限管线

难点：

- 容易把权限理解成简单 allow/deny。

处理方式：

- 拆成策略、作用域、审批、沙箱、审计五层。
- 解释为什么 Agent 越强，权限边界越重要。

### 7.4 上下文管理

难点：

- 容易把上下文管理和长期记忆混为一谈。
- 容易只理解 token 裁剪，不理解信息优先级。

处理方式：

- 先区分上下文、记忆、文件、摘要、检索结果。
- 再解释压缩、裁剪、召回和优先级。

### 7.5 记忆系统

难点：

- 容易以为记忆会自动影响模型。

处理方式：

- 强调记忆必须被召回并放进当前上下文才会影响回答。
- 区分用户偏好、项目事实、历史经验和临时状态。

### 7.6 Hooks 和生命周期

难点：

- 容易把 Hooks 当成插件系统。

处理方式：

- 先解释生命周期节点。
- 再解释 Hooks 是在关键节点插入可控行为。

### 7.7 Subagent 和 Coordinator

难点：

- 容易把 Subagent 当成普通工具调用。

处理方式：

- 先区分普通工具调用、后台任务、Subagent 和多 Agent 协作。
- 强调上下文隔离、任务边界、结果整合和冲突控制。

### 7.8 MCP 和 Skills

难点：

- 容易混淆 MCP、工具、插件、Skills。

处理方式：

- MCP 解释为外部能力接入协议。
- Skills 解释为可按需加载的任务知识和流程包。
- 工具解释为可执行动作。

### 7.9 Plan Mode

难点：

- 容易理解成普通 todo list。

处理方式：

- 强调 Plan Mode 是一种先规划、再执行、再验证的工作流约束。
- 和普通 Agent Loop、目标循环、任务系统做对比。

## 8. 学习路径

### 8.1 快速理解路径

适合先建立主干：

```text
Preface -> 01 -> 02 -> 03 -> 04 -> 07 -> 09 -> 15
```

重点理解：

- Claude Code 是什么类型的 Agent Harness。
- 对话循环如何驱动工具和行动。
- 权限、上下文、Subagent 为什么是 Harness 的核心机制。
- 如何从零构建一个简化 Harness。

### 8.2 系统学习路径

适合完整掌握：

```text
Preface -> 01 -> 02 -> ... -> 15 -> Appendices
```

每章按“导读 -> 原文 -> 整理版拆解 -> 检查点”的顺序学习。

### 8.3 实战迁移路径

适合想自己实现 Harness：

```text
02 对话循环
03 工具系统
04 权限管线
07 上下文管理
09 Subagent
12 MCP
14 Plan Mode
15 Build Your Own Harness
```

每章都要输出一个小练习，最后组合成一个最小可运行 Harness。

## 9. 第一阶段产出计划

第一阶段只做结构和导读，不急于改写完整正文。

建议顺序：

1. 编写 `README.md`，说明本整理版定位、学习方法和目录。
2. 编写 `source-mapping.md`，记录原课程章节到整理版章节的映射。
3. 编写 `glossary.md`，统一解释高频术语。
4. 编写 `00-preface.md`，把原课程前言改写为学习导读。
5. 选取 2-3 个最核心章节试写完整整理版：
   - 对话循环
   - 工具系统
   - 上下文管理
6. 根据试写效果再铺开其他章节。

## 10. 质量标准

每章完成后必须满足：

- 能明确对应原课程章节。
- 不改变原课程主线。
- 不遗漏原课程关键机制。
- 每个复杂概念都有先导解释。
- 至少包含一个流程图、表格或结构化拆解。
- 至少包含 3 个学完检查点。
- 明确说明该机制对通用 Harness 的启发。

## 11. 不做事项

当前阶段不做：

- 不逐字翻译整本课程。
- 不重排成完全不同的课程。
- 不生成大量章节正文。
- 不引入本地已有教程作为主线。
- 不把内容改成纯 Claude Code 使用手册。
- 不在没有逐章校对原课程的情况下写定稿。

## 12. 成功标准

当整理版完成后，读者应该能够：

1. 沿着原课程顺序学习，但明显降低理解门槛。
2. 看到复杂机制时，先知道它解决什么问题，再理解它如何实现。
3. 在每章结束后能说出该机制的 Harness 抽象意义。
4. 最终能把 Claude Code 的架构思想迁移到自己的 Agent Harness 设计中。
