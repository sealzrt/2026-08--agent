# 核心术语表

本文档用于辅助阅读《御舆：解码 Agent Harness · Claude Code 架构深度剖析》。解释重点不是追求定义完整，而是帮助读者在学习时避免概念混淆。

## Agent

Agent 是能围绕目标进行多轮推理、调用工具、观察结果并继续行动的系统。

在本课程语境中，Agent 不是单次模型调用，也不是普通聊天机器人。它通常包含模型、上下文、工具、权限、循环控制和外部状态。

## Harness

Harness 是包在模型外面的工程运行环境。

模型负责推理和决策，Harness 负责把模型的意图变成可执行、可控、可观测的行动。它通常包括工具系统、权限系统、上下文管理、记忆系统、日志、任务调度、Hooks、Subagent 和评估机制。

一句话：

```text
Agent = Model + Harness
```

## Agent Loop

Agent Loop 是 Agent 的基本运行循环：

```text
用户输入 -> 上下文 -> 模型响应 -> 工具调用 -> 工具结果回填 -> 再次调用模型
```

循环会一直进行，直到模型给出最终回答、达到停止条件，或被权限、错误、预算等机制中断。

## Conversation Loop

Conversation Loop 强调对话消息如何驱动 Agent 行动。它关注的是 `messages` 如何被构造、追加、压缩和传回模型。

它和 Agent Loop 很接近，但视角更偏消息流和对话状态。

## Message

Message 是模型输入输出中的结构化消息。

常见角色包括用户消息、系统消息、助手消息、工具调用消息和工具结果消息。Harness 需要维护这些消息的顺序和语义，否则模型很难理解当前任务状态。

## Tool

Tool 是 Agent 可以调用的外部能力，例如读文件、写文件、执行命令、搜索、调用 API、查询数据库。

工具不是普通函数那么简单。完整工具系统还需要定义参数 schema、执行入口、权限检查、错误处理、结果结构和日志记录。

## Tool Call

Tool Call 是模型请求 Harness 执行某个工具的动作。

关键点：模型通常只“提出调用意图”，真正执行工具的是 Harness。Harness 执行后还要把结果回填给模型，让模型继续判断下一步。

## Tool Registry

Tool Registry 是工具注册表，负责告诉模型有哪些工具可用，并负责把工具名映射到真实执行逻辑。

它解决两个问题：

- 模型怎么知道自己能用什么。
- Harness 收到工具调用后该执行哪段代码。

## Permission Pipeline

Permission Pipeline 是工具执行前后的权限控制流程。

它通常不只是简单的允许或拒绝，而包括策略判断、作用域限制、用户审批、沙箱隔离、执行审计等环节。

## Sandbox

Sandbox 是隔离执行环境，用来限制 Agent 或工具能访问的文件、网络、命令和系统资源。

它的核心作用是降低自动化执行带来的风险。

## Context

Context 是当前模型调用时能看到的信息集合。

它可以包括系统指令、用户消息、历史对话、文件片段、工具结果、检索内容、任务计划和被召回的记忆。

上下文不是长期记忆。上下文强调“这次调用看见什么”。

## Context Management

Context Management 是选择、组织、压缩和裁剪上下文的过程。

它要解决的问题是：模型窗口有限，不能把所有信息都塞进去。Harness 必须决定哪些信息保留，哪些压缩，哪些丢弃，哪些需要重新检索。

## Memory

Memory 是跨会话或跨任务保存的信息。

记忆本身不会直接影响模型。它必须被召回并放进当前上下文，模型才能使用。

常见记忆包括用户偏好、项目约定、历史决策、长期事实和任务经验。

## Recall

Recall 是从记忆、文件或知识库中取回相关信息的过程。

好的 Recall 不只是搜索关键词，还要判断当前任务真正需要什么信息，以及这些信息是否仍然可信、相关、不过期。

## Compression

Compression 是把长上下文压缩成短摘要或结构化状态的过程。

它不是简单删字，而是要保留任务目标、关键决策、当前状态、未完成事项和重要约束。

## Hook

Hook 是在 Agent 生命周期的某个节点插入自定义行为的机制。

例如工具调用前、工具调用后、提交前、任务完成后，都可以通过 Hook 做检查、记录、拦截或自动化处理。

Hook 不是普通插件。它更强调生命周期节点和控制流。

## Lifecycle

Lifecycle 是一次 Agent 任务从开始到结束经过的阶段。

理解生命周期后，才能知道 Hooks、权限、日志、状态保存和验证应该放在哪些节点。

## Subagent

Subagent 是被主 Agent 派出去处理子任务的独立 Agent。

它通常有自己的上下文和任务边界，适合处理可并行、可隔离、结果可汇总的工作。

Subagent 和普通工具调用不同：工具通常执行一个确定动作，Subagent 会进行一段独立推理和执行。

## Fork

Fork 是从当前上下文分叉出一个独立工作分支。

在 Subagent 场景中，Fork 可以让子任务拥有必要背景，但不污染主上下文。子任务完成后，主 Agent 只需要接收总结或结果。

## Coordinator

Coordinator 是负责拆分任务、分配子任务、收集结果和处理冲突的协调者。

在多 Agent 系统里，Coordinator 的质量往往决定协作是否有效。没有清晰边界的多 Agent 协作很容易重复劳动、互相覆盖或输出难以整合。

## Skill

Skill 是可按需加载的任务知识包或流程包。

它通常包含某类任务的操作步骤、领域知识、约束、模板或辅助脚本。Skill 的价值在于避免把所有知识都塞进基础提示词，而是在需要时加载。

## MCP

MCP 是 Model Context Protocol，用于让 Agent 通过统一协议接入外部工具、资源和服务。

可以把 MCP 理解为一种能力接入层。它不是某一个工具本身，也不是简单插件市场。

## Plan Mode

Plan Mode 是先规划、再执行的工作流约束。

它不是普通 todo list。它的关键价值是把需求理解、任务拆解、执行顺序、风险和验证方式在动手前明确下来，减少 Agent 直接执行时的偏航。

## Streaming

Streaming 是模型或 Agent 逐步输出中间结果的方式。

它不仅影响用户体验，也影响 Harness 如何处理长任务、工具状态、取消、恢复和实时反馈。

## Trace

Trace 是一次 Agent 运行的结构化记录。

它通常包含输入、模型响应、工具调用、工具结果、错误、耗时、token 使用和最终输出。Trace 是调试和评估 Agent 的基础。

## Evaluation

Evaluation 是判断 Agent 输出或执行过程是否达标的机制。

它可以是规则检查、断言、测试用例、人工评分，也可以是模型评估。没有评估，Harness 很难稳定迭代。

## State

State 是系统在某个时刻的状态。

在 Agent Harness 中，状态可能存在于消息、任务文件、内存、数据库、工作区文件、Trace 或外部服务中。理解状态放在哪里，是理解 Harness 架构的关键。

## Orchestration

Orchestration 是对多个步骤、工具、Agent、任务和验证流程进行编排。

它关注执行顺序、依赖关系、失败处理、重试和结果汇总。

## 常见混淆

| 容易混淆的概念 | 区别 |
|----------------|------|
| 上下文 vs 记忆 | 上下文是本次调用看见什么，记忆是跨会话保存什么 |
| 工具 vs MCP | 工具是具体能力，MCP 是接入能力的协议层 |
| Hook vs Skill | Hook 是生命周期扩展点，Skill 是按需加载的知识或流程包 |
| Subagent vs Tool Call | Subagent 会独立推理和执行，Tool Call 通常是执行一个确定动作 |
| Plan Mode vs Todo List | Plan Mode 是工作流约束，Todo List 只是任务列表 |
| Trace vs Log | Trace 更强调一次运行的结构化链路，Log 更偏事件记录 |
