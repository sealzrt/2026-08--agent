# 前言导读：这门课到底在学什么

原课程入口：<https://lintsinghua.github.io/#preface>

## 1. 先明确学习对象

这门课表面上讲的是 Claude Code，实际更重要的学习对象是 Agent Harness。

Claude Code 可以看作一个具体样本。通过分析它，读者可以看到一个真实可用的编程 Agent 外层系统需要处理哪些问题：

- 如何维护多轮对话状态。
- 如何让模型调用外部工具。
- 如何控制工具权限和执行风险。
- 如何管理上下文窗口。
- 如何保存和召回记忆。
- 如何用 Hooks 扩展生命周期。
- 如何派发 Subagent 处理独立任务。
- 如何接入 MCP、Skills 和外部能力。
- 如何用 Plan Mode 约束复杂任务执行。

所以阅读时不要只问：

```text
Claude Code 是怎么做的？
```

还要问：

```text
如果我要设计自己的 Agent Harness，这个机制解决了什么工程问题？
```

## 2. 原课程为什么难

原课程难，不是因为概念孤立地难，而是因为它经常同时处理三层信息：

1. Claude Code 的产品行为。
2. Agent Harness 的架构机制。
3. 通用工程系统的设计权衡。

例如“上下文管理”这一类章节，读者可能会同时遇到 token 预算、消息裁剪、压缩、记忆召回、文件状态、任务状态和模型输入结构。如果没有先建立主线，很容易觉得每个词都懂，但不知道它们如何组合。

本整理版的作用，就是在进入原文细节前，先搭一层学习脚手架。

## 3. 推荐阅读方法

每章建议按这个顺序学习：

1. 先看整理版的“本章导读”。
2. 再读原课程对应章节。
3. 回到整理版看“核心概念拆解”和“常见误解”。
4. 用“学完检查点”自测。
5. 最后看“和 Harness 的关系”，把 Claude Code 机制迁移成通用设计原则。

不要一开始就追求记住所有术语。更好的顺序是：

```text
先知道问题 -> 再理解机制 -> 再看细节 -> 最后做迁移
```

## 4. 学习主线

整门课可以看成从一个最小 Agent Harness 逐步长出来：

```text
对话循环
  -> 工具系统
  -> 权限管线
  -> 配置系统
  -> 记忆系统
  -> 上下文管理
  -> Hooks 生命周期
  -> Subagent
  -> Coordinator
  -> Skills
  -> MCP
  -> Streaming
  -> Plan Mode
  -> 自建 Harness
```

这条主线背后的问题是：

```text
模型已经能推理了，外部工程系统怎样让它稳定、安全、可扩展地完成真实任务？
```

## 5. 三种学习路径

### 5.1 快速建立主干

适合先建立整体理解：

```text
前言 -> 第 1 章 -> 第 2 章 -> 第 3 章 -> 第 4 章 -> 第 7 章 -> 第 9 章 -> 第 15 章
```

重点理解 Agent Harness 的骨架：

- Agent 编程范式
- 对话循环
- 工具调用
- 权限边界
- 上下文管理
- Subagent
- 最小 Harness 组装

### 5.2 按原课程系统学习

适合完整掌握：

```text
前言 -> 第 1 章 -> 第 2 章 -> ... -> 第 15 章 -> 附录
```

这种路径最稳。每章都不要跳过“学完检查点”，否则后面章节会越来越难。

### 5.3 面向自研 Harness 学习

适合想把课程内容迁移到自己的系统：

```text
第 2 章 对话循环
第 3 章 工具系统
第 4 章 权限管线
第 5 章 设置与配置
第 7 章 上下文管理
第 8 章 Hooks
第 9 章 Subagent
第 12 章 MCP
第 14 章 Plan Mode
第 15 章 自建 Harness
```

这种路径需要边读边画架构图，并记录每个机制在自己系统中的最小实现方式。

## 6. 阅读时的关键问题

每章都可以用这 6 个问题检查理解：

1. 这个机制解决什么问题？
2. 如果没有这个机制，Agent 会在哪些场景失败？
3. 这个机制的输入是什么？
4. 这个机制的输出是什么？
5. 它和哪些模块有依赖关系？
6. 它是 Claude Code 特有设计，还是通用 Harness 原则？

如果这 6 个问题答不出来，说明还没有真正读懂这一章。

## 7. 学习时要避免的误区

### 7.1 把课程当成使用手册

这门课不是教你记命令，而是教你理解 Claude Code 背后的系统结构。

命令和功能会变化，但 Harness 的问题结构更稳定。

### 7.2 把模型能力和 Harness 能力混在一起

模型负责推理，Harness 负责状态、工具、权限、上下文、执行和观察。

学习这门课时，要经常问：这件事是模型完成的，还是 Harness 完成的？

### 7.3 只看最终答案，不看过程

Agent 的关键不只是最后输出什么，而是它如何一步步调用工具、观察结果、修正计划和收敛目标。

所以 Trace、Hooks、权限和上下文都很重要。

### 7.4 把所有机制都一次性实现

读完课程后，不应该直接追求完整复刻 Claude Code。更合理的做法是先实现最小 Harness：

```text
对话循环 + 工具系统 + 权限检查 + Trace
```

再逐步加入上下文管理、记忆、Hooks、Subagent、MCP 和 Plan Mode。

## 8. 学完前言后的检查点

读完前言和本导读后，你应该能回答：

1. 为什么说 Claude Code 是学习 Agent Harness 的好样本？
2. Agent 和 Harness 的边界是什么？
3. 为什么工具系统、权限系统和上下文管理是 Harness 的核心？
4. 为什么不能把记忆简单等同于上下文？
5. 读这门课时，应该如何区分产品行为和通用设计原则？

如果这些问题还不清楚，建议先阅读 [appendices/glossary.md](appendices/glossary.md) 中的 `Agent`、`Harness`、`Agent Loop`、`Tool`、`Context`、`Memory` 条目，再进入第 1 章。
