# 本体论 + Agent 学习教程方案（10 章白话版）

> 一句话定位：把"本体论"从哲学课上拉下来，用**大白话 + 真实业务例子**讲清楚——本体论是什么、怎么建、怎么让 AI 真正懂业务。
>
> 本版按两段深度视频整理的核心观点重构（第一性原理 × 本体论 × AI Agent），章节从 20 章压到 **10 章**，全部白话讲解。

## 0. 一页纸讲清楚本体论（第 0 章，先读这个）

### 0.1 本体论到底在说什么

用数据库类比：本体 = 「表结构定义 + 外键关系 + 校验规则」。

| 本体术语 | 数据库类比 | 白话 |
|---|---|---|
| 类 Class | 表 | 有哪些"东西"的类型（合同、项目、风险） |
| 实例 Individual | 数据行 | 某个具体的东西（合同 HT-001） |
| 属性 Property | 字段 | 每样东西长什么样（金额、编号） |
| 关系 Relation | 外键 | 东西和东西怎么连（合同→约束→项目） |
| 约束 Constraint | 校验规则 | 什么是不允许的（金额必填、验收条款必须明确） |
| 行为 Action | 存储过程/触发器 | 每样东西能干什么、什么情况触发什么（评分>80 自动升级审批） |

一句话：**本体 = 业务世界的概念地图 + 游戏规则**。传统系统"存数据"，本体系统"理解数据"。

### 0.2 五个易混概念（同一问题贯穿）

| 概念 | 白话 | 生活类比 |
|---|---|---|
| 本体论 | 定义概念和关系 | 字典 |
| 知识图谱 | 存具体事实 | 档案柜 |
| RAG | 从文档翻原文 | 原文库 |
| 记忆 | 记住刚才聊了什么 | 便签纸 |
| Agent | 干活 | 调度员 |

它们不替代彼此：LLM 负责说话，本体负责懂世界，图谱负责关联，Agent 负责行动。

### 0.3 本体论给 AI 带来什么（四个能力）

1. **懂关系**：合同→约束→项目，多跳查询不用猜
2. **懂约束**：工具参数类型/必填/枚举自动校验
3. **懂规则**：沿本体关系推演（延期>7天→风险）
4. **懂边界**：高风险动作识别 + 人工审核

### 0.4 本体论的价值分四个层次（不止给 AI 用）

| 层次 | 价值 |
|---|---|
| 传统软件层（不用 AI 也获益） | 业务知识不随人员流失消失；收拢零散 if-else；统一跨系统语义 |
| AI/Agent 层 | 稳定业务世界模型防幻觉；支撑多跳推理；本体=AI 外部持久记忆 |
| 架构层 | 业务逻辑和代码解耦；一套底座支撑 BI/自动化/告警/AI 助手；推理可审计 |
| 组织资产层 | 沉淀为可迭代更新的数字化业务资产 |

### 0.5 落地心法（第一性原理 × 本体论）

- **第一性原理**：先想清楚要解决什么业务判断（供应商值不值得合作？客户质量如何？），不是先买模型再找场景
- **本体论**：搭建业务底盘（实体/关系/规则/行为）
- 比喻：**第一性原理=想清楚去哪；本体论=搭底盘；大模型/Agent=发动机和驾驶系统**
- 落地顺序：定位业务判断 → 梳理依赖实体关系 → 盘点信息载体（数据库/文档/代码/人脑）→ 最后才接 AI

## 1. 教程定位

面向两类读者：

- **业务/项目人员**：不关心 RDF/OWL 术语，想搞懂本体论能解决什么业务问题、怎么落地
- **AI/Agent 开发者**：理解本体论如何增强记忆、RAG、工具、工作流、权限、HITL

学完目标：能独立把一个业务场景（如合同风险管控）跑通"上传→建模→规则扫描→风险确认→人工审核"闭环。

## 3. 两个贯穿案例

1. **合同风险管控**（主案例，覆盖全教程）：合同HT-001 → 自动建模 → 功能清单对齐 → 规则扫描 → 风险审批 → 图谱展示
2. **供应商合作价值评估**（第 04/10 章案例）：采购异常 → 比价 → 超标 → 升级审批；"同一模型 4 天 → 2 小时"的经典案例

## 4. 白话写作规范（每章统一）

1. **开场**：扎心问题或场景故事引入，不用"本章目标"开头
2. **一句话说清**：核心结论大白话（"说白了"）
3. **口语化**："你/我们"对话口吻；术语出现立即解释；禁黑话（实体归一化/语义约束等）
4. **类比优先**：字典/档案柜/便签纸/地图/绳子/门禁卡/发动机
5. **例子贯穿**：合同系统 + 供应商案例，每个概念落到例子
6. **结构**：开场问题 → 一句话 → 小节（表格/例子）→ 真实例子 → 动手试试 → 一句话总结
7. **图**：每章 1-2 张简单 mermaid，图后跟"读图要点"；能用表格就不用图
8. **代码**：技术章节保留最小可运行片段（SPARQL/规则 DSL/interrupt），讲解全人话；代码块必须成对

## 6. 技术路线

教程以 Python 为主，保持组件可替换：

- RDF/SPARQL：第 06 章最小示例（RDFLib）
- 规则推理：第 06 章规则 DSL 演示（"延期>7天→风险"）
- 向量检索：第 07 章补充文档检索
- LangGraph：第 09 章 HITL 中断恢复最小示例
- 完整项目：对照本体论驱动的实施项目落地（如 Ontology/web 系统：Nuxt3 + SQLite + 规则引擎）

原则：**先本地后服务化、先单点后闭环、先白话后术语**——每个概念都先让人听懂，再给最小可运行代码。
